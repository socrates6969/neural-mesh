# lessons_h21 (R9-E multi-step research sessions; synthetic-until-validated)
- In a research session the ladder is retrieval (+.29 q / +.18 ok) >> per-step verification (+.21 q / +.32 ok, +50% cost) > replan-with-reformulation (+.07 q / +.11 ok at ~0 cost) >> exact tools (+.02 q / +.05 ok) ~ routing; decomposition-specific gain over a single agent that already has retrieval+tools is +.09 q in the specialist generator and ~0 in the latent-factor generator and with a dominant agent (-.05). Same ordering as g18, with the retrieval confound made explicit (ss-react control).
- A verifier that can only see LOCAL errors must run at the SOURCE step; wrong inputs propagate through it. That is why per-step verification beats final-answer checks here, and why it is worthless when the verifier is uninformative (vq=0: +.01 ok for +1.4 calls) or the budget cannot afford it (beta 1.3: +.016).
- Components that look good in isolation can sum to a loss: the pre-declared whole stack (adds cross-source READ verification + vote-when-low) LOSES to its own sub-stack L5 in 13/17 worlds (-.04..-.06 ok, +.4..+.9 calls): cross verification is redundant with the search-step title check and its stale-source false flags cost re-searches; best-of-3 per step costs +130% for less ok-per-cost than verification. Always report the leave-one-out ablation of the stack.
- The posterior gate (verifygate::PosteriorGate) ties always-verify wherever verification pays, because the tuned scale rv ~ 1/mu saturates (plateau rv 8-32 at mu .03); it only cuts waste (-6..-11% calls at equal quality) when verification is genuinely unprofitable, and even then keeps ~1.2 checks/session where 0 is optimal. rv is an exchange-rate parameter (rv ~ 1/mu), not a learned quantity.
- A "no information" control must cap what retrieval can ever return (coverage), not just its hit rate: my first version let query reformulation conjure the answer (L5 ok .575 in the no-info world). Even fixed, retrieval-based arms are WORSE than memory-only there (-.04..-.09 q at up to 2.7x cost) because nothing abstains: a missing lever worth a study (abstain / fall back to memory after repeated failed retrieval).
- A "rare errors, expensive verification" control needs errors to be rare relative to 1/mu: at mu .03 even ok .90 still pays for verification. Check the verification-free ok before naming a control "rare".
- Sample efficiency was a null: the keyword-warmed routers sit at their asymptote by task ~100; retrieval/verification carry the gain (tte-own 0/0/17).
- Process: grid edges were hit on the tuning seeds (extended before reading held), and a control-definition bug was found only after reading held results (disclosed, everything rerun, unfixed run kept). Look at every control's absolute numbers for plausibility BEFORE the held look.
