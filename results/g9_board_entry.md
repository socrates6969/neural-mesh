### VERIFY REQUEST — W10 — G9-A CRITIC: which verifier design earns its extra calls? (g9_critic, g9_critic_sweep)

WORLD (fixed in `critic_worlds()` before any policy was run; world A11 was ADDED AFTER the first run, see negatives): KB of 40 entities (8 families x 5 siblings) x 6 attributes, current + (50%) stale value per fact. A task asks for 1 claim (family A: fact QA) or 4 claims (family B: a small report); a claim is a lookup or a derived value (e.a1 +/- e.a2).
A fixed per-task evidence pool of (entity, attribute, value, date, source) snippets comes from "retrieval": current doc w.p. p_ret (.9), second independent source .5, stale doc .6, sibling-entity doc .4, 3% wrong values per source, optional poisoned newest snippet.
Generators = 5 agents with hidden agent x family error multipliers (.35-1.95 x eps), routed by the real `research::ResearchSession` (warm hebbian-robust, reuse on, delay 15, 60% of outcomes revealed). Errors have 4 REAL types: stale value, wrong entity (sibling's value), unsupported (fabricated), arithmetic slip (derived claims only); each type has its own persistence across re-samples of the same agent (stale .8, wrong-entity .7, unsupported .1, arithmetic .15).
Common random numbers: first drafts are identical across arms (checked: acc_first identical in every arm of every world), so paired differences are tight. net(c) = accuracy - c * (extra agent calls + 0.1 * evidence-tool runs); c = 0.05 is the headline (a call costs 5% of a success); a tool run (retrieval-side string/number check, no LLM) is priced at 0.1 call (assumption; sensitivity below).
13+1 worlds: A1 mixed (eps .2), A2 stale-heavy, A3 hallucination-heavy, A4 arithmetic-heavy, A5 all-errors-persistent, A6 all-errors-random, A7 weak retrieval (p_ret .45), A8 poisoned evidence (40%), A9 rare errors (eps .03), A10 CONTROL zero errors, A11* single-source + 50% poisoned (post hoc), B1 report mixed (4 claims), B2 report rare, B3 CONTROL report zero errors.

ARMS (all knobs tuned on seeds 1-8 over 6 tune worlds A1,A2,A3,A4,A9,B1; picks in results/g9_critic.json `picks`): `none`; the EXISTING research.rs critic through the real ResearchSession: `exist-flat(weak)`, `exist-hier(weak)` (SecondOpinion / HierSecondOpinion gate; the second agent is a checker that does NOT see evidence: catch .25 stale / .35 wrong-entity / .6 unsupported / .45 arithmetic, 5% false alarm per claim - MY model of a weak second reader) and `exist-flat(strong)` (catch x1.6, 2% false alarm); `self-consistency` k=3 (2 extra samples of the same agent, per-claim plurality); `support-any(naive)` (claimed value appears in any snippet); `support-entity` (entity+attribute-matched snippet supports, recency-blind); `latest` (newest matching snippet); `agree` (per-source newest values, >= 50% of the sources must back the claim; derived claims recomputed from the same votes); `cascade` (agree, inconclusive -> self-consistency); `auto` (= agree + an ONLINE precision gate: only reroute while the delayed graded outcomes say P(first draft wrong | flagged) > estimated error of the rerouted draft + price of the calls); `gate+evidence` (the research.rs gate decides WHEN, the evidence verifier is the checker, charged as a full agent call); `ev-substitute` (sensitivity: deliver the evidence value instead of rerouting); `oracle` (perfect detector, ceiling). Repair for all flag-based arms = reroute to the best OTHER agent (as research.rs) and re-verify; an unresolved flag is delivered marked "unverified".

NEGATIVES / RIGGING RISKS (blunt):
 1. The evidence critic is handed PARSED, STRUCTURED evidence (entity, attribute, value, date, source). Real retrieval returns free text that must be parsed; every extraction error acts like lower p_ret in the sweep above. The +0.05..0.07 headline therefore needs "retrieval x extraction recall of the current fact >= ~0.65", which I did not measure on any real text.
 2. I defined the error types in terms of the same snippet structure the verifier reads (a stale error is detectable because a stale-dated sibling snippet exists; a wrong-entity error because sibling snippets carry the entity). Real LLM errors need not align with retrievable contradictions; recall .94 is a property of this construction. The existing critic's checker is MY weak model (no evidence); a real second agent with retrieval access would behave like `agree` and a real one without it could be better or worse than my catch rates.
 3. The reroute goes to the best OTHER agent, who is usually worse than the routed one (routing learned who is good): flagged-but-correct drafts are replaced by a worse draft ("harm" column in the log, 0.9% of tasks in A1, 6% in A11). This, not the flag itself, is what makes low-precision verifiers net-negative.
 4. A11 was added AFTER the first run because A8 (poisoning) left `agree` positive; it is a post-hoc stress world, flagged as such. It shows the failure mode that A8 hides (no redundancy).
 5. The tool price (0.1 call) and c grid {.02,.05,.10} are assumptions; the sweep shows the sign pattern of the A1 cell is stable for tool price 0-1 at c=.05 (not re-checked per world; results/g9_critic.json carries net for tool price 0/.1/.3/1.0 in every world). Self-consistency looks bad mostly because k-1=2 extra calls are charged on EVERY task; it wins at c=.02 in A3/A4/A6 (+.028/+.018/+.042 vs none).
 6. Worlds A1-A11 and B1-B3 share the machinery; family B (4 claims) is a structural variation, not an independent world. B1 wins (+.0089), B2 rare and B3 zero-error lose: with 4 claims the false-flag rate per task is 16% (any of 4 claims), so the break-even moves to higher eps.
 7. `auto` lowers but does not remove the zero-error control cost (-.0066 A10, -.0066 B3): the price of running the verifier on every task (0.1 call each) plus the false-flag reroutes of its first ~100 tasks.
 8. First-draft error in the tables (e.g. A1 .103) is AFTER routing to the better agents, i.e. about half of eps; a worse router would give the critic more to do.
RECOMMENDATION: leave `critic: None` as default (unchanged). If an evidence-aware verifier is added, make it opt-in, per-source-voting, with the online precision gate, and document the break-even (see results/g9_proposed_patch.md P1). Do not enable the evidence-free second-agent gate or self-consistency by default.

### VERIFY REQUEST — W10 — G9-C MULTI-STEP dependent sessions (3-5 steps, query k+1 written from the evidence of step k) on real MiniLM / BGE vectors (g9_multistep)

WORLD: session = user states a setup once (step 1: a REAL g1 user query of concept (T1, d*), any of clean / typo / terse / chatty), then L-1 further procedures of the same detail pool (L uniform 3..5; topics of a pool visited in random order, cycled if the pool has < L topics; pools with >= 3 topics: env, db, cloud, lang, os, pay). The query of step k+1 is machine-written from the TOP-1 DOCUMENT of step k: the agent reads that document's detail (full gazetteer; 478/480 topical docs readable and all correct) and fills one of its surface forms into a clean g1 query template for the next topic (5760 follow-up texts per corpus, generated by `py/g9_chains.py`, embedded with the on-disk MiniLM/BGE). A wrong detail therefore propagates; a document from another pool leaves the session `stuck`. Gold = concept (T_k, d*). 300 sessions per seed; common random numbers across arms.
POLICIES on top of nine frozen retrieval systems (bm25, mini, mini+spell, mini-hybrid, mini-final, bge, bge+spell, bge-hybrid, bge-final; no re-tuning): `none`; `local` = verify the top-1 document's detail against the detail the QUERY states (pool gazetteer, strict: the top-1 document must positively confirm it, else take the best top-20 document that does); `pin` = local + keep the detail the USER stated in step 1 and use it instead of the evidence-inherited one when writing later queries. Controls: `indep` (each follow-up built from the GOLD detail = no propagation); degraded verifier (fewer known surface forms, detection noise); worlds `clean-step1` (only clean step-1 queries) and `typo-step1` (only typo queries).

NEGATIVES / RIGGING RISKS (read first):
 1. The verifier's gazetteer is the generator's own surface-form list (3 forms x 8 details x 11 pools) matched with word-boundary rules, and the corpus differs between siblings in exactly that one slot. The +0.16..+0.37 is therefore an UPPER BOUND set by template structure: the sensitivity rows (1 of 3 forms: +0.03..0.07; 10% wrong detections: -0.14 for `local`) are the realistic envelope, and I have no measurement of attribute extraction on real text. `bm25/local` beating every dense system without verification is a symptom of this, not a retrieval insight.
 2. The "control where verification should not help" does not exist cleanly: in `clean-step1` verification still adds +0.18..+0.38 (dense systems +0.18..+0.22) because sibling confusion of the FOLLOW-UP queries (clean, machine-written) persists. The honest negative controls are the degraded verifiers (0 forms = no-op; noise = harm), not a world.
 3. Follow-up queries are copies of the evidence's detail in clean template text, no typos, no paraphrase; in real sessions the carried context is messier. Depth: sessions are 3-5 steps but only up to 4 distinct topics per pool, so L=5 revisits a topic (a "re-verify" step).
 4. Strict vs lenient is a design choice I fixed AFTER seeing the lenient run first (lenient was my original code; I changed to strict after finding 2 undetectable docs matter, then ran both and report both). Held-out 31-60 / confirm 61-90 on another corpus agree within 0.01 on every cell shown, but both corpora come from one generator.
 5. Session success counts ONLY the top-1 document; P@3/R@3 count the 2 relevant documents per gold concept; neither measures answer quality.
RECOMMENDATION: if multi-step research sessions are shipped, (a) keep the user-stated constraint (`pin`), (b) verify retrieved evidence against stated attributes only with an extractor measured at >= ~90% accuracy on the target text, (c) otherwise leave retrieval as is. SUMMARY OF WHAT IS ACTUALLY NEW (measured, simulated): (1) the shipped second-agent critic does nothing useful in a world with 4 real error types (neutral at best, -0.0003..-0.004 net in low-error/control worlds); (2) an evidence-reading, per-source-voting verifier with an online precision gate adds +0.04..+0.07 net (A1-A6, base retrieval) where retrieval surfaces the current fact >= ~65% of the time, is ~0 to negative below ~50% retrieval or when evidence is poisoned without redundancy, and costs 0.007 (auto) to 0.014 (agree) in zero-error controls; (3) W1's "MiniLM+hybrid > BGE-alone in routing" reproduces on two fresh corpora but only in the sibling-heavy world and as a lexical-lever effect (350-450 tasks faster to half the headroom); (4) in dependent multi-step sessions an attribute check on the retrieved evidence dominates the choice of embedding model, but only if the attribute extractor is near-perfect. None of this is evidence about real agents; every effect size is conditional on the assumption listed next to it.
