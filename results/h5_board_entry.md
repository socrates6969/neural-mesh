## What changed in src/compact.rs (all opt-in; `max_rows == vocab_cap == prune_mass == 0` = R3 behaviour)
* Layout (exact transform of the state, no logic change): rows are kept SORTED by feature id (no `(id,slot)` index: -4 B/row), the touched-agent mask is `ceil(n/8)` bytes instead of 8 (-7 B/row at 6 agents, -4 B at 32), which also lifts the limit from 64 to 128 agents (u128 compute, scratch arrays const-generic 64/128 so <=64-agent brains pay nothing).
* (a) bounded state: `CompactConfig::max_rows` (per-brain row cap, VALUE-based eviction = lowest decayed guard-evidence mass first, batches of 12.5%, `EvictPolicy::Hash` is the ablation), `Vocab::bounded`/`SharedVocab::bounded`/`CompactConfig::vocab_cap` (bounded vocabulary: lowest-hit non-keyword strings evicted in batches, keyword strings pinned, hit counters halved on every pass, recycled slots carry a new 7-bit generation in the id's top bits so a stale row of another brain can never alias a new string; stale rows are swept on that brain's next update).
* (b) cells: `Fx12`/`Q12` (12-bit, really bit-PACKED, `P12` column) and `Fx8` study types; `prune_mass`/`prune_dev` cell pruning (extra lever, see below). u16/q16 enc/dec no longer call `round()` / divide (floor(x+.5), reciprocal multiply) and `decide` is one pass over the raw ids with one row lookup each (see latency).
* (c)/(d): compact BINARY state `to_bytes/from_bytes/save_bin/load_bin` (delta+varint ids, raw masks, bit-packed cells, default config = one flag; exact round trip incl. all 5 cell types, truncation/magic/precision-mismatch rejected), state-only form `state_bytes/from_state_bytes` for cold brains, `BrainPool` (LRU hot set + cold blobs, exact reload).

## NEGATIVES / caveats (blunt)
 1. One R3 test expectation changed: `byte_accounting_is_exact_for_the_u16_layout` now asserts the NEW layout (4+ceil(n/8)+4+2+2 B per row, was 8+8+4+2+2); the other 10 R3 tests are unchanged and green. The u16 representation is no longer bit-identical to R3's (rounding/reciprocal change): equivalence is re-established here, the f64/f32 instances remain bit-identical to the shipped router.
 2. The two-sided TOST at +-0.005 with 60..160 paired seeds cannot certify big-64/128 even for the baseline; certification needed 360 seeds, and +-0.003 is certified only in the 3 six-agent worlds. Stage 2 reuses seeds 91-250 from stage 1 (top-up 251-450 alone also passes).
 3. The bounded-vocab result rests on worlds whose tail tokens carry no signal; the only informative-tail control is the row cap, which loses up to 0.05 in sim worlds. Do not read "keywords-only vocabulary is free" beyond these synthetic worlds; measure on real traffic (rare-but-informative tokens would be evicted by hit count).
 4. Multi-brain shared bounded vocab: big-32 only CERTIFIED90 (see above); the keyword table is shared by design (`fork_blank`), so brains over one prototype cannot have per-user keyword maps.
 5. 12-bit/8-bit cells: not equivalent (behaviour changes, 8-bit weights lose 0.011 in sim-fixed), small byte savings, slower; cell pruning saves 1-3% at a passing setting. Neither is recommended. bf8/bf12-style failures of R3 are confirmed for u8; u12 is non-inferior but not equivalent.
 6. Cold pool: only exact and cheap to reload for small brains; for trained 32+-agent brains the blobs are 86-90% of the hot size and a reload costs 30-116 us, so the real win is the bounded vocab / shared vocabulary, not spill.
 7. `Vocab::bytes_estimate` is an estimate (use the counting allocator, which all agents/GiB figures use); Windows commit-charge column in h5_mem.json is noise. Latency numbers come from a box with 9-80% background CPU (other workers): ratios only.
 8. Limits kept: plain Hebbian rule only (meta/weighting/ucb/agg rejected), agent count fixed, now <= 128 agents; not wired into CLI/serve. A `CompactRouter` is not internally synchronised.
Recommendation (nothing is made default): keep `CompactRouter` u16/q16 with the new layout and 128-agent limit; for open token streams enable a bounded (shared) vocabulary (it is the largest lever that passes in every world: -74..-89% of brain+private-vocab bytes in the tail/open worlds (f=.125 .. f=0), subject to caveat 3); use hash32 when no persistence of feature names is needed (zero vocabulary bytes, identical decisions here, collision risk ~n^2/2^33); use binary state for save/load (-54..-62% vs the R3 JSON); do NOT use row caps below the signal-row count, 8/12-bit cells, or cell pruning.
