### VERIFY REQUEST — W14 — NATIVE LOCAL TOOLS MODULE (`src/tools.rs`) + generator->verify pipeline harness (`g13_tools`)
Files: **src/tools.rs** (new, std-only; one line `pub mod tools;` appended to src/lib.rs), src/bin/g13_tools.rs, src/bin/g13_common/mod.rs, results/g13_{selfcheck,tune,held,confirm61-90,controls_held,controls_confirm61-90,sens_held,sens_confirm61-90}.{json,log}, results/g13_run_all.sh, results/g13_board_entry.md. No Cargo.toml / Cargo.lock change, no crate, no network, no process spawning, no git commit.

Honest ceiling (read this first): tools + retrieval + verification make exact sub-computations reliable and let a checker reject wrong claims. They do NOT make the frozen model smarter. This is a SIMULATION whose agent behaviour is seeded (ungated error grows with difficulty; tool-call formulation errors are real string mutations of the spec; the verifier sees a clean spec with probability qv). The tools themselves are real code and are exercised for real on every simulated call. The size of the lift is a function of those assumptions; section 6 shows where it vanishes.

What is in tools.rs: `Tool` trait (name, cost, cacheable, deterministic `call(input)->Result<String,ToolError>`, `call_metered`), `Registry` (name->tool, optional result cache with hit/miss/cost-saved accounting, FIFO-bounded), tools: `Calc` (exact i128 rationals, overflow-checked, precedence parser, depth/length limits), `Units` (conv/sum/dim/same with dimension check), `Csp` (finite-domain solver + certificate checker, node limit), `Identity` (grid identity check, <=2 vars), `Sandbox` (own tiny integer/list interpreter: step limit, live-memory limit, var/nesting/program-size limits, no I/O by construction), `LookupTool` (key/value tables), `Verifier` (re-computes a claim: calc = exact + independent f64 path, units = recompute + reverse conversion, csp = certificate check / re-solve for "unsat", identity = larger shifted grid, sandbox = re-run, lookup = re-lookup; returns `accept` / `reject: why`), `ToolSelector` (learned tool selection: per-feature x tool optimistic cell means, discriminativeness-weighted pooling, warm-start `prior()`), `tool_features()` (shape tokens of a spec).

 * `selfcheck` (results/g13_selfcheck.log; ~7200 generated tasks, both generators, native ground truth computed independently in the bin): for all 6 kinds the real tool == native truth on 100% of canonical specs, the verifier accepts 100% of those correct outputs, rejects 100% of the wrong claims it is shown (n wrong = n), 0 tool errors.  * Limits of this evidence: the verifier re-uses the same exact evaluator for calc/units/prog (plus an f64 path for calc and a reverse conversion for units), so a systematic bug in the parser would not be caught by it; unit tests + native truth are the independent check. The identity tool is a grid test, not a proof (documented).
