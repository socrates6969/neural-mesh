# lessons_h11 (R5-C token efficiency; synthetic-until-validated)
- Cost model first: in the multi-step session the bill is generator completion (48%) + base prompt (19%) + verifier (21-41%); injected notes are 4%, encoder/retrieval compute 0.001% (it needs a ~1900x higher compute price to reach 1%). In a doc-QA session the injected docs are 48%. Only levers that remove generator calls, verifier calls or context tokens move the bill; embedding compute-once and retrieval gating do not.
- Verification is the lever in the multi-step loop (-27% cost at dq -.0005, ties g18 L4 online stopping); a constant posterior threshold fails (low-quality worlds, expensive verifiers): gate on break-even (1-m)*Rv >= cv. The verifier-price swing (x.25 -> -16% saving, x2 -> -36%) matters more than any tuning.
- The context-size knee is a parameter, not a constant: real MiniLM rank profile + (rho=.7, eta=.03) gives k=1 (cost -32%, success +.01 vs k=3); the analytic sweep over (rho, eta, d, doc length, mu) puts it at k=1 in 183/324 cells, k=2 in 74, k>=3 in 67; at mu .1 with long docs k=0. h6's k=2 and this k=1 are both products of the assumptions.
- A verified-answer memo is worth exactly (exact-repeat rate x hit saving) and needs three safeguards (store verified only, reverify on hit, evict on bad grade); without them it saves 83-90% by dropping 0.15-0.5 success; it loses where one text can carry different intents; semantic keys are strictly worse than exact keys. Build a text-unique control (ctl-uniq) or the "control" repeats too.
- Cost-aware routing is a quality-cost trade, not a free lunch: with prices tracking capability it saves nothing (P) or -19% cost for -.041 success (D); it only pays with price-independent cheap-and-good agents (random-price sensitivity: -1..-5% at equivalent quality) or when quality is cheap (mu >= .1). Hindsight oracles show large headroom but exploit realised noise.
- The exchange rate mu (quality per unit cost) decides the ranking (at mu .3 never verify wins); report the frontier, not one tuned point.
- Process: a first gate/world design was changed after seeing held-out 31-60 (constant-tau gate; z1 abstain gate; grid at the edge; no text-unique control) - disclosed; the confirm runs are clean. Check grid edges and add the control that makes the lever's "free" assumption fail BEFORE the held-out look.
