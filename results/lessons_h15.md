# H15 (R7-A) lessons
- The H1 "rare catastrophic HNSW build" (fixed crate, ~0.5% of builds lose 8-37%, recall@10 ~.67) is ROOT-CAUSED: a SECOND bug, distinct from the g17 reverse-edge one. `search_layer` early-returns empty when `points_by_layer[layer].is_empty()`, but layer-0's explicit list holds only points whose TOP level is 0; if the FIRST TWO inserted points both draw level>=1, layer 0 is still "empty" when point #2 descends, so it gets no layer-0 neighbour -> the layer-0 graph splits into >=2 permanent weak components and one component is unreachable from the entry point.
- Rate is exactly 1/M^2 (M=8 -> 1.57%, M=16 -> 0.4%, M=32 -> 0.10%), INDEPENDENT of N, dim, ef_construction, and data distribution (iid/clustered/low-dim). This is why H1's M=8 unit test saw it at ~1%. At the production M=16 it is ~0.3-0.4%.
- One-line fix, additive to the g17 patch: `if layer != 0 && ...is_empty()` in search_layer. Validated: 0 failures on all forced [1,1] and all 10 natural rare seeds; graph byte-identical (FNV hash) to the current crate on 100% of the 99.6% non-triggering builds; recall/build-time/latency unchanged. Proposed in results/h15_proposed_patch.md (NOT applied to hnsw_rs_patched; director's call).
- To make OS-random-level HNSW builds reproducible, inject the level sequence: patch LayerGenerator with a thread-local seed/forced-level hook (default-off, zero effect unused). Essential for bisecting rare build-RNG bugs.
- DETECTOR: an exact layer-0 weak-component count is a PERFECT and cheap catastrophe detector (comps>1 iff catastrophic; 0 false/0 miss over 18k+ builds; ~0.5-11ms). Sampled self-query audit is weaker on clustered/near-duplicate data and MUST tolerate distance<=1e-6.
- Strict-id self-miss OVER-COUNTS on duplicate-heavy data (an item's duplicate ties at distance 0 and wins top-1): dup5 -> 43% "catastrophic" by strict id but the graph is NOT disconnected (comps baseline) and items are findable at distance 0. Use distance-tolerant audit / connectivity, not strict-id self-miss, as the health metric.
- No-crate-change mitigation ranking: modify_level_scale(0.2) removes the trigger (and the g17 mode) at ~no cost but collapses the hierarchy and prints a library warning; else audit_and_repair (one connectivity check or ~100-sample distance-tolerant audit per build + ~0.6% rebuilds). A single rebuild with fresh levels repairs with prob ~1-1/M^2.
