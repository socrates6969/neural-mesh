### VERIFY REQUEST — K3 — EXTRACTION + VERIFICATION ON REAL STRUCTURED DOCUMENTS (k3_*)

**Honest framing (read first).** This measures the ACCESS/EXTRACTION layer of the system (flattened text -> structured values -> checks -> answers); it does NOT make the frozen LLM smarter or give it knowledge. Ground truth is REAL STRUCTURE on disk (markdown pipe-table cell grids; Cargo.toml via tomllib; CHANGELOG headings; Cargo.lock). Everything that is NOT real is labelled: the flattened/reflowed text renderings and prose template families are SYNTHETIC perturbations of the real grids (author-written, so the "unseen" families are optimistic about real unseen text), and the "plain reader" in the downstream section is a seeded NOISE MODEL whose constants are ASSUMPTIONS (h19 values, swept). Extractor and verifier are hand-written python (ideas ported from h19: span offsets, span re-parse, scale evidence, footing, cross-source, abstain; h19's scanners were bound to generated fact schemas so no code was copied). No Rust was written (py/k3_*.py only; no cargo build; no src/ or Cargo.toml edits; no network/downloads; no git commit; no results from other workers modified).

**Real files used (read-only).** (a) 241 distinct documents with markdown tables / 714 raw pipe tables / 249 usable (unique row+col keys, >=2 numeric cells): `neural-mesh/results/*.md` (incl. research_board.md, g*/h* board entries), `neural-mesh/DESIGN.md`, and `C:/Users/mariu/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/<crate>/{*.md,docs/*.md,*/*.md}` (58 crates carry usable tables, e.g. hashbrown, ellip, engram-rs, micro-hnsw-wasm, oxiarc-*, napi, tenflowers-*). (b) `<crate>/Cargo.toml` for 1200 vendored crates, `<crate>/CHANGELOG.md` dated headings (165 crates, 4060 entries), repo `Cargo.lock` (679 packages), `<crate>/LICENSE*` (1062 copyright lines). (c) survey of `$`/%/size/timing numerics in the same markdown (see section 7). Personal/credential files not touched.

**Rerun** (python only, ~4 min, deterministic; corpus fnv `1744236539a5b5fd` must reproduce): `bash results/k3_run_all.sh` (= `PYTHONIOENCODING=utf-8 python py/k3_main.py all`; subcommands `corpus|extract|verify|controls|struct|down`; `--splits=dev,held,confirm`). Output: `results/k3_all.log` (+ `k3_extract.json k3_verify.json k3_controls.json k3_struct.json k3_down.json`, samples `results/k3_samples.txt`). Files: `py/k3_{data,render,extract,induce,verify,eval,stats,adv,struct,realtext,main,main_helpers,main_verify,main_controls,main_down,quick}.py`, `results/lessons_k3.md`.

**Protocol.** Split BY FILE: dev = 16 repo files (hash(filename) even; 46 tables, 4557 gold cells), held = 10 other repo files (28 tables, 3746 cells), confirm = vendored crates (78 docs, 58 crates, 175 tables, 1884 cells; disjoint from the repo). Extractor v1 = built from the DEV split only; v2 = v1 + fixes found on DEV renders (nolabel split continuation, merged-header heuristic, blank-cell positional assignment, accounting/unicode/trailing negatives, EU separators, ± ) AND a broader unit list; v3 = v2 + generic prose template induction (`k3_induce.py`, tuned on dev renders of families F1-F3 with the family regexes disabled). Verifier "full" = broad independent unit table + span re-parse + ambiguous separators + footing; "narrow" = verifier restricted to the extractor's own dev knowledge (shared blind spot). Gold canonicalises units (ns/us/ms/s, B/KB/MiB, %, K/M/B -> base units); each F1 is reported strict (canonical value) AND lenient (number-as-written accepted) so unit-semantics errors are separable from structure errors. Layouts: pipe, ws (whitespace-aligned), wrap (header wrapped over lines), csv, split (continuation block without row labels), merged (header merged, single spaces), prose families F1-F3 (dev) and H1-H4 (held-out), value formats v0 / thousands / K-M-B / negatives (paren, unicode minus, trailing minus) / percent<->fraction / unit rewrite (cell or moved to header) / EU separators / mix. Real prose lines around each table are included as distractor text. CI = bootstrap over documents (files); downstream = paired bootstrap over documents, Holm (per condition over 7 arms, and GLOBAL over all 126 extractor x split x condition x arm tests). TOST margin not used (no equivalence claim made).

**POST-HOC changes / contamination, disclosed.** (1) After the first verifier run on confirm I fixed: gold unit table lacked `minutes/seconds/hours` that the verifier knew (corpus hash changed `c3e1...` -> `1744...`); footing tolerance made precision-aware (`~15s` total vs 14.62 summed gave a false flag; strict 1% flagged 3/10 real total tables, precision-aware 1/10); verifier number parser now strips `>= <= > <`. (2) Ambiguous-separator evidence made document-global after seeing held output (v1 extractor drops EU cells so evidence from its own facts was empty). (3) v2/v3 unit list was written after a census of units in ALL splits (I printed it), so the confirm gain from v1 -> v2/v3 on unit-bearing cells is NOT a blind transfer result; only v1 is a pure dev->confirm transfer test. (4) While developing the v3 inducer I printed dev-split numbers for the H families (design-adjacent, not blind); held/confirm numbers for v3 were first printed in a sanity run after freezing. (5) Header wrapping renderer fixed to not split words mid-word (dev). (6) The ws layout's thousands-comma collision with the csv detector (below) was observed and NOT fixed.

So the generated-corpus qualitative story transfers (phrasing collapse, knowledge-bound verification, rare footing, extraction gain conditional on verification and reader strength); the magnitudes do not: on real crate tables the dominant error is unit semantics (not layout), verification is worth +0.08..+0.10 for a dev-only extractor (vs +0.01 in h19), and the induction scanner buys phrase robustness only where tables are large enough to repeat a template.

**BLUNT: what real documents break.** (1) Unit lexicons: 64% of crate gold cells carry a unit/suffix/percent/thousands marker (only 36% are bare numbers); the dev-trained extractor silently mis-scales the 25% with ns/us/MiB/s/KB/min/km/mW (micro sign vs Greek mu, `~99ms`), and `x 1.14`, `1.5-2x`, `8/8`, `>= 4KB` cells are not plain numbers at all. (2) Small tables: 69% of crate tables have <10 numeric cells (median 7; repo tables median 52-66); template induction and footing need redundancy that is not there. (3) Free-text columns, blank cells, wrapped labels, side-by-side tables, transposed orientation: silent mis-assignment of 7-85% of extracted facts and NO check here catches it (span re-parse agrees with itself). (4) Thousands separators collide with the csv detector in whitespace tables. (5) "total" rows are rare and rounded/non-additive; copyright-year and monotone-date plausibility rules false-flag 26-35% of real files. (6) Confidence from layout structure is miscalibrated (ECE 0.16-0.24) and tau-abstention loses recall for no precision. (7) The prose scanner emits ~16 false facts per 1000 numbers on non-table prose. (8) Merged single-space headers: 0.00-0.60 and unreliable (author heuristics). (9) Everything is still a SIMULATION on real grids: no PDFs/OCR/ligatures/column interleave/images; unseen families are author-written; reader noise and the layout mixture are assumptions; unit knowledge in v2/v3 is contaminated; the "full" verifier's unit table equals the gold's, so its catch is an upper bound for a verifier that knows every unit.
