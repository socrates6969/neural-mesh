# lessons_h19 (R9-C document extraction + verification; synthetic-until-validated)
- (h19) Extraction is what moves document-QA quality in the sim (+0.10 acc, 30/0/0 seeds, 3 generators, held+confirm, at ~0.36-0.40x the cost of a full read); verification adds a small but consistent +0.010..0.014 (mostly by turning silent paper-claim miscounts into fallbacks); retrieval over blocks is net NEGATIVE (-0.006..-0.012; +0.05 on long papers, -0.07..-0.09 on financial because the block drops the scale/header line); routing contributes ~0 (agent skill spread is tiny next to document noise). All conditional on ASSUMED reader-noise constants.
- (h19) Extractor F1 collapses on phrasing it was not built for: 0.995 seen vs 0.52 unseen (field F1 0.16 KPI .. 0.90 table cell); layout difficulty is not the driver, phrasing is. A dev-calibrated abstention threshold is useless (dev has no wrong extractions: tau* = 0.05 at F1 1.000); calibrate on a set that contains wrong extractions.
- (h19) The verifier's catch rate is a knowledge property, not a code property: 0.79 with author-anticipated variants vs 0.12 when restricted to the extractor's own (dev) knowledge, at the same 2.3% false-flag rate. A verifier that shares the extractor's blind spots re-confirms its errors (same as g13/g21: 90% vs 19%).
- (h19) Span re-parse catches 100% of value-vs-own-span errors (scale/sign/transposition/decimal) but only the cross-cell checks catch WRONG-CELL errors: financial footing 0.87, KPI cross-checks ~0.6, paper results tables 0.12-0.15 (no redundancy). Accounting footing never fired on natural errors (they are uniform column-scale errors, footing is scale-invariant); on real tables footing applies to ~0.7% of tables and both candidates failed (non-additive totals).
- (h19) Most downstream question types (ratios, growth) are scale-invariant, so scale errors that crater extraction F1 barely change answers; judge extractors on the downstream metric, not only on F1.
- (h19) Unverified extraction is worse than reading directly for a strong reader (break-even at ~0.15-0.2x the assumed noise, plain acc ~0.97); verified extraction ties it. Extraction arms on documents that need no extraction cost 1.15-1.18x plain (accuracy equal, TOST +-0.01 true), and an uninformative verifier (random 15% flags) is NOT harmless (-0.0094/-0.0099, TOST fails).
- (h19) Real-text check (unlabelled): extractor parser agrees with a trivial parser on 86-91% of real cells (unit-glued cells `15 µs`, `MiB/s`, `NaN`, bracket CIs are the misses); independent re-parse found 2 verifier bugs (leading-dot decimals, `KB`) before any held run; 39% of currency amounts in real prose carry a B/M/K suffix the dev extractor ignores (verifier would catch).
- (h19) Generator/extractor co-development trap: the "unseen" bank is author-written, so every unseen number here is optimistic about real unseen text; and ablation arms must not leak through a neighbouring check (two ablations were wrong until fixed).
