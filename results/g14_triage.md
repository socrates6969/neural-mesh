## (b) SAFLA self-feedback loop (core/metacognitive/learning.py, adaptive_safety_boundaries.py, delta_evaluation.py)
- `AdaptationEngine.adapt_system(feedback)`: TRIGGER = `performance_gap >= adaptation_threshold` (config default 0.2, constant, no calibration, no variance
  or sample-size handling). CORRECTION = append two hard-coded modifications: `learning_rate = min(lr*1.1, 0.5)` and "increase performance-goal priority 0.1".
  `expected_improvement = min(gap*0.5, 0.2)` and `confidence_score = 0.8` are literal constants, not measured.
- `learn_from_experiences`: groups (exact serialized context string, action) -> success rate; "promising" if rate > .5 (single example gets confidence .6), else "may be
  ineffective" with confidence 1 - rate. No smoothing/prior, `_contexts_similar` is string equality. `recommend_action`: argmax raw success rate; default confidence .5.
  This is a strictly weaker version of our discounted-Beta tables.
- `AdaptiveSafetyBoundaries`: when a constraint value EXCEEDS its threshold, `_adapt_constraint` RAISES the threshold by `adaptivity_rate` (capped at max). Violations loosen the
  safety limit; as a safety mechanism it is backwards (it ratchets toward never firing). Do not copy.
- `DeltaEvaluator` (g8): hand-weighted sum of four deltas. Nothing learned.
- Reusable trigger/calibration algorithm: none. Security/hygiene: large FastAPI/MCP surface, Dockerfiles, fly.toml, installer.py; not examined for payloads, not run.

## (c) Retrieval crates as algorithms vs our stack (hnsw_rs + MiniLM + hybrid BM25 + token-overlap rerank; g1 numbers: mini-final hit@1 .936/.921, ceiling about .95)
- `ruvector-hybrid` (fusion.rs, bm25.rs): BM25 k1=1.2,b=.75; three fusions: min-max weighted blend (alpha .7), RRF with k=60 over 4k candidates per list, RSF (per-list min-max, alpha .5). Flat exact dense index. We have BM25 + tuned-alpha already; RRF/RSF is the only thing not tried -> R3. No claim of gains is made on real text; benchmark is synthetic.
- `ruvector-gnn-rerank`: `GnnDiffusionReranker`: cosine kNN graph over the candidate set (k_graph 8), then `s_i <- .6 s_i + .4 mean_{j in N(i)} s_j` for `hops` rounds; `GnnMincutReranker` same but only across edges with cosine >= 0.5, similarity-weighted. Despite the names there is no GNN, no learning, no min-cut. It is built to cancel i.i.d. noise from QUANTISED scores. Our error mode is not noise but sibling confusion: smoothing pulls a candidate toward its near-identical siblings, which is exactly Rocchio PRF, measured at -.009 / -.010 MRR (g1, Holm losses) for MiniLM. The 0.5 gate does not separate siblings (MiniLM sibling cosine ~.8+). Verdict: no. (Their own recall test uses synthetic random vectors with injected i.i.d. noise.)
- `ruvector-attention` (20k lines; flash, MLA, MoE, hyperbolic, sheaf, PDE, info-bottleneck, speculative attention): a transformer-attention toolkit needing trained weights; we have no ML runtime in Rust and no learnable reranker. A parameter-free "attention over candidates" is softmax(q.k/tau) = temperature-weighted cosine = PRF again. no.
- `ruvector-attn-mincut`: Dinic max-flow used to gate attention logits (sparsify softmax). Needs an attention layer. no.
- `ruvector-mincut` / `ruv-neural-mincut`: dynamic min-cut data structures; no retrieval role at our size; g8 already judged memory-admission O(c^2) overkill. no.
- `ruvector-core` HNSW: a thin wrapper around hnsw_rs (our same crate). Defaults m=16, ef_construction=100, ef_search=100 (npm wrapper: m=32, efc=200, ef=100); ours m=16, efc=200, ef=64: nothing to learn. BUT see R2: it vendors a PATCHED hnsw_rs and ships regression tests for the bug (tests/hnsw_issue_773_*). Other core modules: mmr.rs (MMR lost 9/9 worlds in our d/f series), conformal_prediction.rs (see (e)), hybrid_search.rs, filtered_search, PQ/OPQ/diskann (flat is faster at our N).

### R2 detail: probable bug in hnsw_rs 0.3.4 (our Cargo.toml: `hnsw_rs = "0.3.4"`)
Source read in `~/.cargo/registry/src/*/hnsw_rs-0.3.4/src/hnsw.rs`, `reverse_update_neighborhood_simple` (line 1229): the loop is `for l in (0..level+1).rev()` over the new point's neighbours at layer `l`, but the reverse edge is written to `q_point_neighbours[l_n]` with `let l_n = n_to_add.point_ref.p_id.0` = the NEW POINT'S TOP LEVEL, not `l`. For level-0 points (about 94% at M=16) l_n == l == 0, correct. For a point of level L>=1 every reverse edge (including those found at layer 0) lands in the neighbour's layer-L list, so that point gets no layer-0 in-edges from the reverse update. Every `Point` allocates NB_LAYER_MAX neighbour slots, so nothing panics; it fails silently. ruvector's tests/hnsw_issue_773_regression.rs documents exactly this ("search() intermittently omitted a stored row"; ~2.8% failure per 3-row index; raising ef_search cannot recover the point) and ships a patched copy; their structural test checks every point is reachable at layer 0 from the entry point. I have NOT run anything; the diagnosis is two independent readings (ours of the registry source, theirs of their vendored copy) agreeing. Impact for neural-mesh: none on the flat default; potentially loses a few percent of stored lessons/cases in HnswIndex / HnswRm (tiered hot store, casebased large). Experiment: (1) build with hnsw_rs 0.3.4 at N in {1k,5k,30k}, dim 128/384, >=20 builds (levels are random), query each stored vector (k=1, ef=512): count misses; compare recall@10 with flat; (2) same with a local copy where `l_n` is replaced by `l as usize` (via `[patch.crates-io]` pointing at a reviewed copy, never an unreviewed download). Acceptance: miss count > 0 unpatched and = 0 patched; any recall@10 change reported with CI. If confirmed, either vendor the one-line fix or keep flat below the N where it matters, and record it in the board as a correctness note (the .96-.99 in H2 is partly this, not just ANN approximation).

## (e) Confidence calibration / selective prediction / conformal / self-consistency usable as a critic trigger
1. `ruvector-core/src/advanced_features/conformal_prediction.rs` (real split conformal for retrieval): calibrate on validation queries with known true neighbours; non-conformity = score (distance), or inverse rank, or normalised distance, of each TRUE neighbour inside the top-100; threshold = (1-alpha) empirical quantile of those scores; prediction set = all results within the threshold. Issues in the code: (i) `calibrate` returns Err if any true neighbour is outside the top-100, so it either fails or only works on easy sets (selection bias); (ii) quantile index `ceil((1-a)(n+1))` is used as a 0-based index and then clamped to n-1 (conservative by one rank, harmless); (iii) coverage is marginal and assumes the calibration queries are exchangeable with deployment queries, which our corpora A-D deliberately are not (A->B,C,D differ in surface forms). The USEFUL property is the set size: size 1 = confident, size >1 = ambiguous -> escalate. That is R1.
2. `ruvector-typesafe-core/loop_gate/sequential.rs` (PairedSequentialTest): betting e-process on discordant pairs only: `W <- W*(1 + lambda*(X - 1/2))`, X=1 iff champion wins the pair, lambda=.5 (factor 1.25 or .75), reject "no improvement" when max W >= 1/alpha (alpha .05 -> 20); latches. Valid by Ville's inequality; it is McNemar's structure with anytime validity. Where it maps: (a) a promotion/regression gate between two arms evaluated on the SAME tasks (needs both arms' outcomes, i.e. shadow evaluation; under bandit feedback we only observe the chosen arm, so the guarded hand-over cannot use it as is); (b) our own harness: sequential stopping of seeds instead of fixed 30 seeds + Holm (compute saver only). The gate also has a ControlArm (champion vs permanent control; alarm if drift < -threshold after min_samples) which is the same as our hand-over benching. Verdict: R5, low; do not expect accuracy gains.
3. Temperature scaling / Platt (typesafe-core): textbook; we already calibrate per-cell Beta posteriors. The one piece we lack is an ECE/Brier readout for the critic's P(fail) estimates (p_l in SecondOpinion::plan); worth adding as a diagnostic in g9-style logs, not as a mechanism.
4. Self-consistency: no code exists in these repos (checked all 475 crates + clean repos for self-consistency, semantic entropy, majority-of-samples, risk-coverage). g9 already implements k=3/5 sampling and found it loses on net (.834 vs .897 none at c=.05, A1-mixed) because each sample is a full agent call.
5. tiny-dancer `voi::decide` (g8 E3) and SecondOpinion are both closed-form VoI; SecondOpinion already prices gain vs cost with discounted Beta posteriors and kappa-optimism; a second VoI formula adds nothing (d1 already showed router-uncertainty triggers fail, only failure-streak works).

### R1 detail (the only trigger experiment I would run)
- Data: results/g1_emb_{A,B,C,D}_{mini,bge}.f32 + g1_corpus_*.json (all already on disk; no new model/download). Pipeline: MiniLM top-k (with the existing spell + overlap-rerank "mini-final") -> trigger -> if triggered, BGE rerank of the top-20 (existing cascade).
- Triggers compared: top1-top2 cosine margin; split-conformal prediction-set size (calibrate alpha in {.05,.1,.2} on the tune split of corpus A: non-conformity = 1 - cos(query, gold doc), threshold as the (1-alpha) quantile with the correct 1-indexed rank, ESCALATE if set size >= 2); softmax(top-k cosines / T) entropy; random escalation as the null; always-escalate and never-escalate as bounds.
- Metrics: hit@1, MRR, R@3 vs fraction escalated (frontier), AURC (area under risk-coverage), empirical coverage of the conformal set on held-out concepts of A and on B, C, D with frozen calibration (reports the shift failure honestly), cost = escalated fraction x BGE query-encode (13 ms) + BGE doc vectors in memory (already counted in g1: 2x).
- Protocol: g1's (tune on id%5==0 concepts, held-out seeds, frozen picks on fresh corpora, paired 95% CI, Holm).
- Honest expectation: errors are concentrated at low margin (siblings), so the frontier should be concave: most of the +.015-.02 cascade gain at ~30% escalation. If the frontier is a diagonal (margin carries no information about errors) that itself is a useful negative. Caveats: synthetic templated corpora (g1 caveat 1); a real-text re-test is the only thing that would change the default; downstream routing gain expected ~0.
