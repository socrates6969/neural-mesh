## Design (declared before running)
* Gate: verify iff `signal <= t`; `t` is fitted ONCE on a calibration split, seeds 101-130 (disjoint from tune 1-8, held 31-60, confirm 61-90; asserted in code), from graded outcomes, then frozen. No online adaptation of t. Nothing else is tuned (W10's `auto` gate cost .02 and g18's L4 k=1,R=1,eps=.1 are their frozen picks).
* Pre-declared threshold rules: **R1 = cost-neutral break-even** (t maximises cumulative net benefit of verifying on the calibration split; "never verify" if no prefix is positive) = headline; **R2 = target error capture .90** (t = 90th percentile of the signal over WRONG calibration items; "never" if < 30 wrong items).
* Two independent generators. **G** = g9 critic world (KB facts + retrieved evidence + 4 real error types; verifier = per-source-agreement evidence check "agree"; reroute to the best other agent), arms are exact per-task selections between "no verify" and "verify" because g9's tracker state is arm independent (so paired differences are tight; unit test: my record-based always/never/auto reproduce g9's Ev(Agree)/None/Auto arms to 1e-9). **H** = g18 orchestration world (3-6 dependent steps, noisy verifier sig_v, retry/reroute, retrieval notes; my gated runner reproduces g18 L3 and L2 bit-for-bit, unit test). 12 G worlds + 12 H worlds fixed in `g_worlds()` / `h_worlds()` before any run.
* Signals. G: synthetic self-reported confidence (correct ~ N(.8,.15), wrong ~ N(.8 - sep*.15,.15), hidden per-agent bias +-.1; sep 1.5 main, .7 weak, 0 uninformative) and retrieval coverage (number of sources holding evidence; AUROC for error ~.50 by construction, it predicts verifier usefulness not error). H: self-reported step confidence (q + N(0,sig_c), sig_c .2 main / .5 weak / independent = uninformative), retrieval margin (strength of the retrieved project note; -mis for a wrong note), router posterior (the orchestrator's own table of delayed-graded mean quality per (agent, step type); the Router trait exposes no posterior).
* Cost accounting (every verifier call counted). G: verifier = one evidence-check execution priced `tp` agent calls (tp .1 = g9 default; tp 1 = an LLM-class verifier; BOTH reported, neither chosen post hoc), reroute = 1 agent call + 1 more verifier execution; net(c=.05) = accuracy - c*(reroute calls + tp*executions); c .02/.10 sensitivity in the json. H: g18's own cost (1/step + .05 retrieval + cv per verifier call) and g18 utility at mu=.03 (headline) / .1.
* Baselines: never, always, W10 online `auto` (G) / g18 L4 learned stopping (H), random-skip at EQUAL TOTAL COST (bisection on verify probability; G exact, H matched on mean cost/task), oracle gate (verify iff truly wrong), best-fair-per-world chosen on the test seeds (conservative).
* Statistics: 30 paired seeds, 95% t-CI, Holm per family; "EQUIV" = whole CI inside +-0.01 (margin pre-declared: 1 point of accuracy / net / quality). Cost-reduction tests are written always-minus-gate (positive = fewer calls/cost).

Take-aways: (1) the gate is safe against shifts to a *lower* error rate or noisier signal in the sense that it stays at or above the better fixed policy at tp .1, but over-verifies (cost), and a threshold calibrated on a regime where verification does not pay ("never") is a disaster when errors become common (H: -.015 util; G: A9->A1 at tp 1 loses 4.2 points of accuracy because it verifies 6% of tasks instead of 33%). (2) Calibration must be repeated per regime (task mix, retrieval quality, verifier price): the optimum t moved between .35 and +inf (G) and .14-.54 (H) across the worlds. (3) Poor signal: at AUROC .68 (sep .7) and tp .1 R1 degenerates to always-verify (no saving); at tp 1 it saves 48% of cost but -1.9 pts accuracy and beats random-skip by only +1.6 pts. (4) With an expensive verifier and common errors (B1, tp 1) the break-even rule stops verifying altogether: it is cost-optimal but gives up 2.9 points of accuracy; use R2 if accuracy must be preserved.

## NEGATIVES / RIGGING RISKS (blunt)
1. **The signals are synthetic.** AUROC .85 is my parameter. Real self-reported LLM confidence is often poorly calibrated and its AUROC for factual errors is unknown here; the ECE rows only show that binning fixes miscalibration, not that real confidences are informative. Everything positive scales with that AUROC (weak-signal rows show it).
2. In world G the verifier's value is a property of g9's construction (parsed structured evidence, error types defined against the same snippets; see W10 negatives 1-2). The savings are real *given* that verifier; the gate does not make a weak verifier good (A7: the gate beats always mainly by avoiding bad reroutes).
3. At tp = .1 the net gain over always-verify is small (+.003): the headline is verifier-call count, not accuracy. At tp = 1 the gain is large but R1 trades away accuracy.
4. World H: no win over the existing online rule; the calibrated conf gate is q-lossy; the best H gate uses the router-posterior signal, which is the orchestrator's own table (not a Router API) and is cheap only if a table like that is maintained.
5. R1 maximises a noisy cumulative sum on 45k tasks; in two cells it picked an interior threshold that is statistically indistinguishable from a fixed policy. Calibration and test come from the same simulator, which flatters the in-distribution rows; the shift section is the honest part.
6. Disclosures: (a) the first full H run (31-60) was made before I added the vs-auto / vs-L4 test families and flipped the sign convention of the cost-reduction families (always-minus-gate); the underlying means are identical (I reran everything and the files above are from the final code); (b) world lists, rules R1/R2, margin, tp grid and c grid were fixed in the source before running; (c) 4 of the 12 H worlds and 12 G worlds are single-parameter variants of the same base (not independent; independence is across generators G/H); (d) the confirm run re-calibrates on seeds 101-130 inside the run (deterministic, identical thresholds), nothing is tuned on 31-60 or 61-90.
7. Not claimed: any accuracy improvement of the generator, any real-traffic effect, any 10x. Defaults unchanged; opt-in primitive proposed in `results/h3_proposed_patch.md` (FixedGate + calibration report + refuse-to-enable guard), not applied.

RECOMMENDATION: ship nothing by default. If anyone wants it: opt-in `FixedGate` fitted offline per regime, enabled only if calibration AUROC >= .6 and >= 30 wrong calibration items, with a monitoring window that disables it (falls back to always-verify) when the observed error rate leaves a band around the calibration rate; prefer R2 when accuracy must be held, R1 when the verifier is expensive. Prefer g18's L4 online stopping in orchestration; use the router-posterior gate only if matching L4 at slightly fewer calls is worth a separate calibration step.
