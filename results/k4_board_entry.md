## HEADLINE (all four: none of the organisation levers beats flat retrieval on recall; only link expansion on its own structure and acquisition-by-gap-log move anything, and those are conditional)
1. AUTOMATIC TAXONOMY (k-means on MiniLM + c-TF-IDF, ward tree over centroids) + two-stage retrieval: NEGATIVE. Every config loses MRR / hit@8 versus flat; the cheapest config within a pre-declared MRR tolerance (-0.005, tune A) scans 84-90% of the docs, loses -.003..-.019 MRR (Holm-sig in 12/14 cells) and the cluster-confidence fallback only buys back recall by falling back to flat. Auto-clusters are NOT domains (NMI vs provenance domain .15-.37) so the h20 "purity" mechanism is weaker still. Real speed gain exists only at recall loss: m=2 of 83 clusters scans 2.7% of docs (426 vs 1034 us/query single-thread numpy) at about -.04..-.10 MRR.
2. KNOWLEDGE LINKS (same-file/section neighbours, rare terms, explicit md links, Cargo.toml deps) + link expansion at EQUAL context budget (k=8; r slots for linked neighbours): NEGATIVE when the graph is not the structure that defined the question (frozen config union_nc, r=1: -.022/-.021/-.004 both-hop recall A held ADJ/SECNEXT/DEP, -.032/-.015/+.007 A confirm, -.001 B confirm); POSITIVE only for the graph that IS the label structure (LE|adj on ADJ pairs +.069 / +.045 / +.046 held / A-confirm / B-confirm; LE|dep on DEP +.014 / +.013) -- circular by construction and tiny vs the oracle edge ceiling (+.19..+.25). Random-link control costs -.02 (TOST fails); single-hop control with the full union graph is TOST-equivalent (-.002). Graph-based query expansion: mixed, mostly negative/small (ADJ -.02/-.015, DEP +.016/-.001, SECNEXT +.005/+.014) and random-neighbour QE gives +.007 on ADJ, so QE gains are not link-specific. Decomposing 2-clause questions into two retrievals (known clause boundary; costs 2 retrievals) beats flat on DEP (+.059 held / +.017 confirm) but loses on SECNEXT held.
3. STALENESS / contradiction between versions (real README versions of 214 crates): small, positive, SIGNIFICANT-ISH but tiny n. On masked-changed-fact queries flat returns the stale paragraph 9-20% of the time; a structural-key / unsupervised-sibling newest-wins resolver raises answer-correct@1 .80 -> 1.00 (held n=35, boot CI [+.03,+.44], Holm .044) and .83 -> .91..1.00 (confirm n=23, ns). The signal "top-1 has a newer same-key version with different text" has recall 1.0 / precision .875 on NUM changes (.875 / .50 on ENT), 0.6% false flags on STABLE controls and 0 on ONLYOLD; the semantic (no-key) resolver loses 1-2 ONLYOLD/STABLE queries (-.003..-.077) and `key` newest-wins hurts ENT queries when the flat top-1 was right by accident (-.13 tune). Structural key reliability: 93.6% of 1806 near-identical paragraph pairs keep the same (crate|heading|ordinal) key.
4. ACQUISITION POLICY (gap log -> priority ranking -> extend simulation): SMALL positive vs random under SYNTHETIC concentrated demand, NOT robust: gap-priority (label-free low-cosine gap detector, AUC .68-.76; softmax-cosine of gap queries to unit "abstracts") raises coverage growth AUC over random by +.019 / +.068 / +.082 (held A / pydoc9 / crates8) and +.024 / +.053 / +.036 / +.021 (confirm A / B / pydoc9 / crates8): 4 of 7 Holm-significant (rec_auc: 1 of 7). Most-recent / largest-first ingestion are no better than random (largest-first loses -.01..-.09). A topic-level predicted prior (topic_pred) is better on pydoc9 (+.13 / +.076) but not on A/B/crates8 (-.005..+.08, ns) and is the WORST arm under drift (-.03..-.07). Controls are NOT clean: uniform demand gives gap-random -.012..+.045 (TOST +-.02 holds in 3 of 7), drift demand costs gap -.04 (pydoc9 held) .. +.03: do not ship as a default; opt-in advisory ranking at best. Oracle (known future demand) headroom is +.41..+.48 cov AUC, so the label-free ranking realises ~5-18% of it.

## DECISION
(a) No taxonomy/two-stage retrieval: flat hybrid+spell stays (recall loss at every useful cost point). (b) No default link expansion; if used at all, only as an opt-in with the graph = the question's own structure (adjacent paragraphs, Cargo deps), r=1-2 slots, and never as a generic union graph. (c) A structural-key newest-wins staleness check is cheap, safe on stable/deleted controls and fixes the stale-answer cases in the (small) version sample: candidate opt-in verifier signal for versioned stores with current-answer intent; needs real traffic. (d) Gap-log based acquisition ranking: label-free gap detection works (AUC ~.7) but the ranking only modestly beats random and fails the uniform/drift controls: advisory only. Defaults unchanged; nothing applied to src/.
