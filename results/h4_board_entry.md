## R4-B1 (h4) memory reduction: tiered memory + forgetting under a hard byte budget  [ALL NUMBERS SYNTHETIC-UNTIL-VALIDATED]

Scope: the system footprint we control (router case store / shared vector memory behind the knowledge router), NOT Claude's internal memory. Quality = routing success of a kernel-regression case router (+ useful-retrieval rate), not LLM quality.
Files: src/tiered.rs (owned; opt-in additions, defaults unchanged, 17 tiered tests green incl. 5 new), src/bin/h4_memory.rs, src/bin/h4_common/mod.rs, results/h4_{predeclare,tune,held,confirm,hnsw,combined}.*, results/h4_combine.py, results/h4_proposed_patch.md.
Protocol: tune seeds 1-8 (hyperparameters only), held-out 31-60, confirm 61-90 (frozen), reference = unbounded memory, paired by seed (common random numbers), margin +-0.01 (strict +-0.005) pre-declared in results/h4_predeclare.md BEFORE held/confirm, TOST + Holm over the main-world family; claim only if EQ in BOTH stages. Two independent generators (A-zipf: recurring Zipf families + 30% one-off noise + drift of 25% of families; B-burst: bursty time-windowed lessons, log-normal benefit, junk traces) + controls (A-allvalued: 500 equally valuable families; A-noreuse: nothing recurs).
Disclosed post-hoc: (1) after tuning I added a pre-held NON-INFERIORITY test (addendum in h4_predeclare.md) and the tiered-int8+merge policy; (2) after the FIRST held/confirm run showed forgetting beating unbounded memory in A-zipf (stale cases), I added a `full-rd` sensitivity reference (unbounded memory + recency-weighted vote, half-life tuned on seeds 1-8 = 500) and re-ran held/confirm/hnsw; earlier outputs kept in results/h4_prev/ (identical for all other rows - deterministic). Merge sim=0.8 was tuned with the pre-freeze value hyperparameters.

### Headline (honest)
1. VALUE-BASED forgetting (recalled-and-helped utility, decayed) is NOT supported: it is beaten by plain FIFO in A-zipf at every budget (value-fifo -0.004 / -0.029 / -0.054 at 50/25/10%, pooled 60 seeds, CIs exclude 0) and by FIFO at 50%/25% in A-allvalued (-0.0085/-0.0091); equal in B-burst. Best tuned decay was the shortest tried (500), i.e. the tuner pushes it toward recency.
2. IMPORTANCE-MERGE (absorb same-label near-duplicates, weights add) is the best consolidation add-on: merge beats value at 10% by +0.019 (A-zipf) and +0.008 (A-allvalued), holds A-zipf@10% bytes with delta +0.0011 held / -0.0016 confirm (NI both stages; EQ(.01) only in held, FAILS Holm in confirm => NOT claimed equivalent).
3. Compression of the cold tier is the one clean "free" saving: tiered-int8 at budget=100% (no item dropped) keeps 59% of bytes at D=64 (41% saving; 57% saving projected at D=384 for the same retained set) with EQ(+-0.005) in BOTH stages in A-zipf, B-burst AND the all-valued control (delta +0.0002/-0.0006, +0.0004/+0.0002, +0.0001/-0.0001). tiered-f16: 72% of bytes (28% saving; 38% saving projected at D=384), also EQ(+-0.005) both stages, but search is 5-7x slower (software f16 convert).
4. Equivalence (+-0.01, Holm, both stages) at 50% bytes holds for lru, merge, tiered-int8, tiered-f16, tiered-int8+merge in A-zipf and for ALL policies in B-burst; at 25%/10% in A-zipf nothing is EQ (FIFO/tiered-int8@25 are significantly BETTER than unbounded: non-inferior, not equivalent). B-burst (recency-sufficient world) is EQ for every policy down to 10% bytes (90% saved).
5. Controls behave: A-noreuse identical at all budgets (harmless). A-allvalued: forgetting costs real quality, roughly proportional to the dropped value: flat policies -0.015..-0.037 @50%, -0.069..-0.085 @25%, -0.118..-0.132 @10% (the entire memory benefit is +0.167 over no memory); tiered-int8 costs only -0.0008 @50% (EQ strict), -0.034 @25%, -0.105 @10% because compression keeps 1.6-1.8x more items per byte. In that world tiered-int8 beats FIFO at equal bytes by +0.015/+0.035/+0.024.
6. In A-zipf, FIFO@25% / @10% is +0.032..+0.039 ABOVE unbounded memory (+0.016..+0.023 above full-rd): that is a router weakness (no recency handling vs mid-stream drift), i.e. stale-case removal, not "forgetting makes memory smarter"; do not read it as a general gain. unbounded `full` is not a quality ceiling in A.

### Frontier / knee (success delta vs unbounded, held/confirm; bytes = final estimate / unbounded at D=64; proj = same retained set priced at D=384)
A-zipf: lru@50% +.0018/+.0017 (EQ); merge@50% +.0030/+.0042 (EQ); tiered-int8@50% (bytes .496, proj .345) +.0003/+.0001 (EQ strict); tiered-int8+merge@25% +.0094/+.0084 (NI, bytes .247, proj .218); merge@10% +.0011/-.0016 (NI only); value@10% -.0206/-.0174 (loss); tiered-int8@10% -.0058/-.0073 (loss, NI fails); tiered-int8+merge@10% +.0070/+.0046 (NI). Knee for an EQ claim: ~50% bytes (65% projected D=384 with tiered-int8). 10% bytes is non-inferior (NI) for merge / tiered-int8+merge / FIFO only.
B-burst: every policy EQ(+-0.01) at 50/25/10% in both stages (<= +-0.003); strict (+-0.005) for most at 50/25%. Memory itself is worth only +0.04 over context-free there.
Latency (search time, mean ns vs unbounded, 2 runs in parallel => noisy, +-10%): dropping items scales it ~linearly: 0.77x @50%, 0.5x @25%, 0.29x @10% (flat store). tiered-int8: 1.5-1.6x @100/50% (cold int8 scan is slower per item than the f32 kernel), 1.2x @25%, 0.6x @10%; tiered-f16 3.8-7x. hnsw backend: no quality difference (value-hnsw@25% 0.5748 vs flat value@25% 0.5717, delta vs unbounded +0.0104 [-0.0008,+0.0217], 10 seeds), search 0.61x of full-hnsw. Hard budget held in all runs (overshoot column 0; the 64-item short ring is exempt from eviction but counted).

### Negatives / caveats
- Value-by-reward forgetting loses to FIFO (headline 1). Recency is the strong simple policy in these worlds; whether real traffic has the same temporal locality is unknown.
- Equivalence margin +-0.01 is only meaningful with these SDs (paired SD of delta ~0.005-0.02); A-zipf has no EQ claim at <=25% bytes.
- D=64 synthetic embeddings; bytes at D=384 are a PROJECTION of the same retained set, not a rerun (a real budget at D=384 would retain more compressed items; also int8 error is relatively smaller there). No real MiniLM/BGE fixture run, no real traffic.
- tiered-int8 / f16 make search slower per item (software conversion); turbovec cold tier unchanged and not re-benchmarked here.
- Router is a simple kernel-regression bandit; a router with recency handling would shrink the "forgetting helps" effect in A (see full-rd rows).
