## 1. Cost model (units, conversions, parameters; `results/h11_cost.log`, `h11_common/mod.rs`)
* 1 TE = one prompt token at the reference (mid-price, pi = 1) generator. Completion token = `r_out` TE (default 4; swept 1/2/4/8). Agent price pi_a multiplies BOTH prompt and completion tokens of that agent's calls; the verifier has its own tokens and a `v_scale` price sweep.
* Per call: generator = base prompt + injected context + completion; verifier call; retrieval = encoder + scan milliseconds; rerank / tool calls are in the model (price 0: no such arm survives; g16/h2 rejected rerank, no tool in these loops).
* ms -> TE conversion: `lam_ms` TE per ms, default 0.0046 = a $0.05/vCPU-hour host (1.39e-8 $/ms) against a $3/Mtok prompt price (3e-6 $/TE). ms inputs: encode 2.6 ms (py ONNX MiniLM, results/f6_py_latency.json; 2.4 ms in results/h1_embed_ident.json), scan 0.02-0.05 ms; measured Rust decision loop 1.8-14 us/task (noisy box). Swept 0.0046 / 0.1 / 1 / 10.
* Embedding compute-once (R4-A1, results/h1_embed_ident.json: encoder calls/decision 3.64 -> 0.98 -> 0.39) is NOT re-run here; it is a price scenario (`embed compute-once`): it changes cost by 0.0% at every lam (encoder compute is 0.001% of a task at the default price; it reaches 1% of a task only at lam = 8.8 TE/ms = ~1900x the cloud-CPU price). It matters for latency / CPU-bound self-hosting, not for a token bill.
* Other scenario knobs (post-hoc, applied to stored resource counts, arms NOT re-tuned): `pc_disc` (prompt-cache style discount on the static base prompt), `ctx_scale` (document length), `v_scale` (verifier price), `embed_once`. 13 scenarios per world in the json (`price_sens`).
* World P tokens (synthetic): step call prompt 500 + 60/dependency (+ 120 per injected note), completion 350 -> S_REF = 1900 TE; verifier = cv x S_REF (cv .3; .8 lat-pricever; 1.0 ctl-rare-pricever). Agent prices: `Cap` = clamp(.25 + 2.5 (mean competence - .4), .25, 3) (better model costs more; a type specialist is cheaper than its capability), sensitivity worlds `Rand` (price independent of competence) and `Flat`.
* World D tokens: call prompt 300 + injected docs (REAL fixture doc lengths chars/4 = 74 tokens, x4 = ~297 TE assumed for a realistic chunk; swept x1/x4/x8) , completion 250 -> S_REF_D = 1300 TE; verifier 250 + the same evidence docs + 40; agent prices .25/.25/1/1/3/3 with caps .50/.50/.68/.68/.86/.86.
* Utility used for tuning and "best fair" picks (g18's convention): `util = quality - mu * (cost per reference call - 1)`, mu = 0.03 (a 1-reference-call increase in cost is worth 3 quality points); `--mu 0.1` reruns everything at the strict rate. mu is a value judgement, not a measurement; the ranking of arms changes with it (section 6).

## 2. Worlds (two independent generators + controls)
* World P = a COPY of the g18 orchestration world (generator A "pipelines" 6 worlds, generator B "latent factors" 4 worlds, 5 controls; instances bit-identical to g18, unit-tested: L2/L3/L4 reproduce g18's quality and call counts exactly) plus agent prices, token accounting and the cost levers.
* World D = a document-QA session on the g16/g1 fixtures: REAL MiniLM+tf-idf query similarity (anchors), REAL hybrid doc rankings and doc lengths, the g16 recurring-concept stream, worlds sib16 / rand16 / sib16-mixed50 / sib16-weakid50 / sib16-drift / sib64 / sib16-dups30 (30% re-ingested duplicate docs) + controls ctl-none (context useless, d = 0), ctl-oneoff (off-topic texts), ctl-uniq (NEW: every query text used once, concepts recur, exact texts do not). Synthetic parts: agent caps/prices, concept difficulty, the context-utility model `fit = (1 - d(1 - U(R)))(1 - eta I)`, `U(R) = 1 - (1-rho)^R` (rho = .7 diminishing returns, eta = .03 dilution per irrelevant doc), verifier flag model (false flag .08, recall .75).
* Protocol: tune seeds 1-8 (P: all 15 worlds; D: panel of 6, sib64 / ctl-oneoff / dups30 / ctl-uniq never tuned), held-out 31-60 (P; D corpus A), confirm 61-90 with the SAME frozen procedure / frozen picks (D: fresh corpus B texts), 30 paired seeds, paired 95% t-CI, Holm per family, TOST +-0.01 on quality (margin declared before the runs), plus non-inferiority (NI: CI lower bound > -.01). EQ columns below are `Holm | raw | NI` counts of worlds.

### VERIFY REQUEST - R5-C - H11-C: what does NOT work in world P (cost saved only by dropping quality, or nothing saved)

## 6. NEGATIVES, CAVEATS, DISCLOSURES (read these first)
1. Everything is synthetic: token counts, prices, agent competence, the context-utility model (rho, eta, d), the verifier flag model, the retrieval-score model of world P. The real parts are the g16/g1 fixture retrieval (rank-relevance, scores, doc lengths, which texts recur and are confusable) and the g18 world structure. No claim about a real bill or real model quality.
2. The memo and knee results are world-dependent by construction: exact-text repeat rate 93.6% in the main D worlds (3.5% in ctl-uniq); the k knee follows (profile, rho, eta, price); the 2-docs-per-concept corpus caps the number of useful docs.
