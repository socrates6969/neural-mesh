HONESTY (read first): everything is a seeded simulation I wrote. It measures whether decomposing a 3-6 step task, routing each step by type, giving each step recurring-project context, verifying steps with an imperfect
checker and re-routing failures raises a graded quality that I defined, and what that costs. It does not measure LLM behaviour, reasoning, or discovery. The sizes of the gains are set by world parameters I chose
(specialist gap, propagation strength, context dependence d, verifier noise, cost of a check); the sensitivity runs show how each one scales and where the gains vanish or turn negative. No "10x", no intelligence claim.

## The world (fixed BEFORE any policy was run; `g18_orch --show` -> results/g18_world_examples.txt, which also prints oracle reference rows)
- 8 agents, 4 step types (lookup, compute, synthesize, check), hidden per-agent per-type competence c. Task = 3-6 steps with dependencies (mean 4.5 steps/task, 1500 tasks per run), a recurring project (10-300 projects) and text features.
- Step quality q = clamp(c + step difficulty + agent noise) x fit(context) x (1 - prop x (1 - q_in)); q_in = mean (generator A) or min (generator B) of the dependency qualities, so an early wrong step propagates. A step is "correct" iff q >= .6; task all-correct = every step correct; graded task quality = mean step q.
  fit = 1 - d_type (1 - neff u): d = context dependence per type (lookup .25, compute .05, synthesize .18, check .08 in A), neff = strength of the retrieved project note (right note) or -.5 (wrong note), u = .5+.5c.
- Verification: signal = q + N(0, sig_v), flag iff signal < .55 (recall is imperfect, false flags exist); cost of one check cv (a step call costs 1, a retrieval .05). Retry/reroute: up to 2 retries, each to the router's pick among untried agents; keep the highest-signal attempt if all are flagged.
- Delayed graded feedback to every learner (60% of tasks, 15 tasks late, noise .05). Common random numbers: the same agent gives the same raw answer to the same step in every arm.
- Generator A (6 worlds, "pipelines"): specialist pool (2 generalists .64, 4 type specialists .90 in own type / .46 off, a lookup+check dual .80, 1 weak .42), template DAGs (mixed / chain / wide), mean-propagation. pipe-main, pipe-chain, pipe-wide, pipe-weakctx (d x.4), pipe-lowrec (300 projects), pipe-badver (sig_v .22).
- Generator B (4 worlds, "latent"): agents from 3 latent factors (cross-type correlated, one agent is usually good at everything), random DAGs (edge prob .35), min-propagation. lat-main, lat-highprop (prop .9), lat-noisyag (noise .16), lat-pricever (cv .8).
- Controls (5): ctl-single-step (1 step/task), ctl-indep-dominant (independent steps + one agent best at every type: decomposition has nothing to specialise), ctl-indep-spec (independent steps, specialists: specialisation without propagation), ctl-rare-pricever (all agents ~.92, noise .06, cv 1.0: errors rare, checks expensive), ctl-equal-agents.
- Reference rows (not policies): oracle-single (best single agent per task), oracle-decomp (best agent per step, no brief), oracle-decomp+ctx (plus perfect brief). Seed-1 numbers in the examples file: pipe-main oracle-single q .487 / all-correct .007, oracle-decomp .672 / .345, +ctx .843 / .939; lat-main .657 / .235, .667 / .295, .819 / .846.

## Arms
Fair single-shot baselines (6, same delayed feedback, one router call per task, task_type = sorted multiset of step types, features = type words + project token): keyword, eps-greedy (tuned), pooled-thompson (tuned), hebbian-robust, warm(hebr) (k tuned = 1), guarded-safe (`defaults::recommended_router`). Reference: `ss-warm+retr` = single-shot warm with the SAME note mechanism (fair control for the retrieval confound).
Orchestrator levels (cumulative; one router per step type = Warm(Hebbian) with the type keyword map, k tuned = 1):
- L1 decompose + route each step by type; L2 + per-step retrieval; L3 + per-step verification, retry/reroute on flag, verification signal used as same-task router feedback and note store; L4 + learned stopping (skip a check when ucb of the flag rate of this (agent, step type) times R is below the check cost, explore with prob eps); L5 + parallel fan-out (independent steps run concurrently: latency = critical path; same-task feedback deferred to task end).
- Ablations: L3-nolearn (no same-task verification feedback), L4-noexplore.
Tuned on seeds 1-8 only, objective over all 15 worlds (3 small grids): baselines (eps (1,0), pts 1, warm k=1), L2 step-router k (=1), L4 R in {.5,1,2,4,8,16} x eps in {.02,.1} -> R=1, eps=.1 with objective = utility at mu .03 (utility = graded quality - mu x (cost per step - 1)). Best fair baseline = best mean graded H1500 among the 6 per world on the held-out seeds (conservative, as in g5).
Protocol: held 31-60 and fresh 61-90 (same frozen tuning, because tuning always reruns on seeds 1-8), paired 95% t-CI over 30 seeds, Holm per family (F1 level vs best fair x 6 metrics x 15 worlds = 450 tests; F2 level vs previous level 7 metrics x 6 pairs x 15 = 630; F3 sample efficiency; F4 level vs single-shot WITH notes).

### VERIFY REQUEST — W19 — G18-C: controls and the "retrieval confound"
(1) Decomposition alone (L1) is NOT a general win: ctl-indep-dominant L1 vs best fair = -.0106 [-.0115,-.0098] graded, -.078 all-correct (Holm LOSS; learning cost of 4.5 routing decisions per task when one agent already dominates); ctl-single-step +.012 (ns; the two routings are the same decision); ctl-rare-pricever +.0025 ns; ctl-equal-agents +.000 (ns); ctl-indep-spec (specialists, no propagation) +.185 (WIN): the L1 gain in generator A is specialisation, with propagation adding more on top (sens: prop=0 L1-bf +.196, prop=.9 +.185, so propagation does not drive it).
(2) L2/L3/L4/L5 "win" in every control against a baseline that has no notes. That is the retrieval lever, not decomposition. Fair comparison F4 = level vs `ss-warm+retr` (single-shot with the same note store; notes are only created from task-level quality >= .6, so single-shot rarely creates them in generator A): graded H1500, 31-60: L3 vs ss+retr A 6W/0L, B 4W/0L, ctl 3W/0L/2ns; L2 vs ss+retr B only 1W/3ns (lat-main +.023 [+.010,+.035]); ctl-indep-dominant L2 vs ss+retr = -.0124 [-.014,-.011] (Holm LOSS) and L3/L4 tie it (+.001/+.000, ns).
(3) Rare errors + expensive checks (ctl-rare-pricever, cv 1.0): L3 spends 9.32 per task vs 4.72 for L2 for the same quality (graded .862 vs .863, all-correct .994 vs .992): utility at mu .03: L2 .862, L3 .830, L4 .859. L4 learns to skip: cost 5.18 (0.45 checks/task, the eps .1 exploration floor) with graded quality +.0007 over L3 (ns) and utility +.0284 [+.0276,+.0291] over L3 (Holm WIN, both seed sets); but L4 does not beat L2 (utility -.003): it recovers all but the exploration floor of the wasted cost. IMPORTANT: at cv = 1.0 the skip is NOT learned from evidence: the prior ucb of the flag rate (.48) times R=1 is already below cv, so L4 never checks except through its exploration floor (L4-noexplore: 0.00 checks, cost == L2). Where the check price is lower the gate does have to learn: sens `rare(HighSkill)` (same agents/errors, cv .1 / .3 / 1.0), 31-60: L3-L2 cost +0.51 / +1.42 / +4.60, L4-L3 cost -0.43 / -1.26 / -4.14, L4-L3 graded -.0003 / -.0001 / +.0007 (all ns), L4-L2 utility(.03) -.0016 / -.0019 / -.0031 (Holm-raw CI excludes 0 on the negative side: L4 still pays a small exploration tax versus no verification at all; 61-90: -.0013 / -.0018 / -.0033). lat-pricever (cv .8, regular errors): L4 .647 vs L3 .666 graded, cost 5.26 vs 12.16, utility(.03) .642 vs .611, vs L2 .636.
(4) Verifier harm: pipe-badver (sig_v .22): L3 is NOT better than L2 (-.0019 graded ns, -.065 all-correct Holm LOSS) because false flags reroute correct steps to weaker agents; L4 recovers it (+.0264 graded, +.156 all-correct over L3), and is the best arm there (.757; best fair .429). Sens: sig_v .4 -> L3-L2 = -.048 [-.051,-.045] graded.

## RESULTS SUMMARY: which level moves quality, by how much (graded H1500, vs best fair single-shot, generator A | generator B; 31-60, confirm within .001-.006)
1. L1 decompose + route per step: +.214 | +.003 (ns). Real only when specialists differ across step types (generator A, and ctl-indep-spec); a LOSS (-.011) when one agent dominates; no regression otherwise. Cost: unchanged (same #step-calls).
2. L2 + retrieval: +.080 | +.067 more (all-correct +.275 | +.103). The largest generic lever in these worlds, but it is the lever I wrote in (d): the F4 control (single-shot given the same notes) shows what is decomposition-specific: L2 beats `ss-warm+retr` by +.29 in pipe-main, only +.02 in lat-main.
3. L3 + verification/retry/reroute: +.026 | +.039 more (all-correct +.089 | +.085), at +50% / +87% cost (pipe-main 4.73 -> 6.97; lat-main 4.72 -> 8.64 per task; ~5.2 checks/task). Positive in 5/6 A and 4/4 B worlds on quality, but utility-negative at mu >= .05; harmful when the verifier is poor (pipe-badver all-correct -.065).
4. L4 + learned stopping: quality ~ L3 in A (+.001), -.008 in B; cost back to L2 + 6-30% (pipe-main 5.04 vs 6.97; checks/task .63 vs 5.19); utility(.03) +.012 over L3 in pipe-main, best arm in the poor-verifier, expensive-verifier and rare-error worlds, but never above L2 where checks are unprofitable.
5. L5 parallel fan-out: quality change 0 (all 15 worlds ns), latency -0.33 (pipe-main, deps/step .98) to -3.5 (independent steps); it is a scheduling effect, not a quality effect, and its reported quality equality is a model property (no contention modelled).
Best overall arm by utility at mu .03: L4/L5 in 9 of 10 treatment worlds (pipe-main .766 vs L3 .753 vs L2 .743).

## NEGATIVES / LIMITS (read these first)
1. Gains are partly built in: single-shot loses because I gave step types distinct specialists (generator A) and a context dependence d; the dominant-agent / generator-B / mono_pen=0 results show L1 is ~0 without specialisation and that the F4 retrieval confound removes most of what looks like an "orchestration" gain in generator B (L2 vs ss+retr: lat-main +.023, other B worlds ns).
2. Disclosure 1 (tuning change): my first full run (kept as results/g18_orch_run1_mu0.1_tuning.*) tuned L4 for utility at mu = .1 over R in {.5,1,2,4}; it hit the never-verify grid edge (R=.5; 0.11 checks/task, L4 ~ L2). I then changed ONLY the L4 tuning utility to mu = .03 and widened the grid to R up to 16 (chose R=1, eps=.1), added the util(.03) metric and the own-asymptote sample-efficiency test, and reran everything. Worlds were not touched. mu is a free value judgement: at mu .1 the honest conclusion is "do not verify at these prices" for most worlds; at mu .03 L4 pays.
3. Verification gain includes best-of-k selection under agent noise (ctl-equal-agents: all agents identical, yet L3 is +.042 graded for +6.3 cost per task; ctl-single-step +.030). It is not all error detection.
4. The retrieval model is a stochastic stand-in (hit prob p_id, wrong-note penalty, notes created from graded success), not the real `Knowledge` index; the replica-vs-real-session check done in G5 was NOT repeated. Single-shot notes are created only from task-level quality, which disadvantages `ss-warm+retr` in generator A.
5. L4 has an exploration floor (eps .1): ~0.1 checks per step forever; it cannot detect a drifting agent or verifier (no drift in any G18 world). L4 loses -.0076 graded vs L3 in generator B (Holm-sig in 2 of 4 B worlds), traded for ~40% less check cost.
6. Costs are my accounting: a step call = 1, check = cv (.3 default), retrieval = .05; no token-length effects; single-shot is charged as many step-units as the decomposed run (a real long single call could be cheaper or costlier). Latency counts checks as cv-length steps; fan-out assumes unlimited parallelism.
7. Baseline set: 6 fair single-shot routers with small grids (best chosen per world on held-out seeds, conservative); no baseline reasons over the whole task text beyond the feature/keyword views given; task_type = multiset signature gives them the composition but not the DAG.
8. Early cost: none of the levels has a worse H250 than the best fair baseline in the treatment worlds (Holm), but ctl-indep-dominant L1 starts -.01 behind. Time-to-target vs the best fair baseline is a floor effect (see B).
9. W10's `g9_multistep` (real embeddings, retrieval chains, verification of top-1) is a different, complementary study; no files shared, no claims about overlap.
