HONEST FRAMING: everything is synthetic-until-validated-on-real-traffic. This studies the SYSTEM's routing/retrieval, not the frozen LLM. NO claim that personas make a model smarter. The persona effect is an ASSUMED parameter (below), and
the end-to-end retrieval quality is an ASSUMED function of the retrieved contexts; what is measured is how much of an assumed effect a router/gate realises and whether it is harmless when the assumption is false.
Baselines are PYTHON re-implementations (eps-greedy, Gaussian-Thompson, keyword-table eps-greedy, keyword-table Thompson; hybrid z(.7)+BM25+spell re-implemented from `src/hybrid.rs`, not bit-compared to the Rust); hebbian-robust / warm / guarded-safe were NOT run. Fidelity of the hybrid replica to Rust is unverified.

## A. ROLE / PERSONA routing (`py/h20_persona.py`)
EXPLICIT ASSUMPTION: quality = clip(comp[agent, domain, subskill] + role_term + N(0,.10)); role_term = 0 generic; `b*g_agent - c` if the invoked role == task domain; `-p - c` if a different role (p mismatch penalty, c ceremonial cost of any role prompt).
Effect worlds (b,p,c): mod (.05,.04,0), zero (0,0,0), harm (-.03,.06,.02), strong (.12,.06,0), hetero (b=.06, per-agent responsiveness g~U(-1,2.2)). Generators: G1 specialist agents + templated text (anchor accuracy .82), G2 latent-factor agents + noisy topic-mixture text (.75), ctl = identical agents (role is the only lever). 10 roles = {scientist, engineer, business_analyst, executive, financial_analyst, commodities_analyst, economist, linguist, psychologist, historian}, 3 sub-skills each, 18 agents, T=1000 tasks, graded feedback revealed for 70%, no extra LLM calls (a role call costs +60 prompt tokens, reported as role-call fraction).
Policies: fair generic baselines eps / pts / kweps / kwts (best fair = best mean on the evaluated seeds, conservative; it was kweps in every non-ctl world); treatments use the SAME agent chooser as kweps (eps tuned) so contrasts isolate the role: oracle_role, anchor_role (static role-descriptor keyword anchors), learned_role (keyword x role bandit from graded outcomes), joint (agent x {generic, anchor role} arms), gate_static (anchor margin >= tau), gate_ab / gate_ab_agent (online randomised A/B of role vs generic on anchor-eligible tasks, residuals vs the agent's keyword estimate, role used only if the lower confidence bound of role-minus-generic > 0).
Tuned on seeds 1-8 only (objective mean + worst-case world): kweps eps .05, eps .1, gate_ab tau 1 / eps_g .1 / z 1.28 (agent variant the same), gate_static tau 4 (tuned to essentially never fire). Held-out 31-60, confirm 61-90 frozen. Holm over 10 worlds x 7 policies (70 contrasts per phase).

Ceiling context (held): best agent per task alone = .866 (G1) / .819 (G2); + oracle role (b=.05) = .916 / .869. The best fair baseline reaches ~.64 / .66 -- AGENT ROUTING headroom (~.2) is 4-10x the whole persona effect.

Findings (all conditional on the stated assumption):
1. Pure persona routing is worth exactly what the assumption gives it: with an oracle role the gain equals b (ctl-mod +.050 = b); with keyword-anchor role detection (acc .75-.83) it is ~acc*b - (1-acc)*p = +.025..+.034 at b=.05, up to +.076 at b=.12. It is ZERO when b=0 (bit-identical to the baseline, by construction) and NEGATIVE (-.034..-.058) when role conditioning is harmful. So "persona routing" is only as good as the (untested) premise; it never beats good agent routing as a lever.
2. Learned role routing from graded outcomes (11-arm keyword bandit) LOSES in every world where the role has a real effect (-.009..-.028, Holm-significant) because b=.05 vs noise .10 is too small to learn through 11 arms in 1000 tasks. Do not ship.
3. Joint role x agent (2N arms) is positive when the effect is real (+.008..+.039; Holm-sig in strong/ctl) but slower than the static anchor role, and it is not harmful in harm worlds (-.004..-.008, ns): the arm structure protects but costs exploration.
4. The online randomised A/B confidence gate is the only role policy that is safe everywhere: equivalent to the baseline within +-0.01 (TOST) in the zero, harm and ctl-zero worlds on confirm (G1-harm -.004 Holm-sig on held, -.001 ns on confirm: its price is the exploration share), and recovers only a FRACTION of the available gain when the effect is real (G1-mod +.007 vs +.031 for ungated anchor; G1-strong +.028 vs +.076) -- it fires on 11-23% of tasks within 1000 tasks. Gate-on-fraction is limited by sample size, not by anything else. Per-agent gating adds nothing measurable even in the hetero world (+.006 vs +.006).
5. The static margin gate tuned on seeds 1-8 collapsed to "never fire" (tau 4) -- the tune objective (mean + worst-case world) prefers safety; the tune table (results/h20_persona_tune.json) shows the trade: tau 1 gives mean +.007 but worst-case -.017.
6. Sensitivity: oracle/anchor/gate all scale ~linearly with b; the harm world shows ungated persona = loss. Early phase (first 250 tasks): gate_ab within +-.007 of the baseline everywhere.

## B. DOMAIN-CORPUS RETRIEVAL (`py/h20_corpus.py`, `h20_syn.py`, `h20_embed.py`, `h20_retrieval.py`)
Corpora (domain label = provenance, `results/h20_corpus_*.json`; text only READ/parsed with `ast`/regex, nothing executed):
- `pydoc9` REAL: docstring prose of installed python packages, 7 domains with >=60 paragraphs: numerics_stats (scipy, mpmath, sympy, stdlib statistics/math), ml_data (sklearn, pandas), language_text (inflect, langdetect, py_rust_stemmers, regex, tiktoken, pyparsing, markdown_it, difflib, textwrap, string, locale, gettext, email, html, unicodedata, codecs), graph_knowledge (networkx, rdflib), web_network (aiohttp, httpx, requests, urllib3, h2, starlette, fastapi, websockets, dns), db_cloud (sqlalchemy, alembic, redis, tomlkit), project_research (this repo's results/*.md + DESIGN.md). 2874 paragraphs (crypto/time domains had <60 usable paragraphs and were dropped).
- `crates8` REAL: README + `//!` docs of the 1200 vendored crates, domain = the crate's own Cargo.toml `categories`: math_sci, encoding(+compression), parsing, datastruct, os_hw, network, text_i18n (7 domains, 832 paragraphs; cryptography 48 dropped).
- `syn10` SYNTHETIC (clearly labelled): word-salad paragraphs of real domain words for the 10 roles with no real text on disk (scientist, engineer, business analyst, executive, financial analyst, commodities analyst, economist, linguist, psychologist, historian), 8 sub-topics each, 15% borderline cross-domain docs, shared confusable words, unique entity token (query carries it w.p. .35). 3200 docs.
- Units = paragraphs of >=3 sentences; query = a held-out sentence (doc = paragraph minus it; h10 S-protocol); typo queries (SYNTHETIC keyboard model, py/h10_embed.py) for 50% of queries; spell corrector = src/hybrid.rs algorithm over the world's doc vocabulary. Embeddings: on-disk MiniLM-L6 via python onnxruntime (cognee venv), fixtures `results/h20_emb_*.f32` (md5 in `h20_fixtures.md5`).
- Controls `+shuf`: domain labels randomly permuted (index labels are noise; the harm model keeps the true domain).
Query pools are disjoint hash buckets (tune / held / confirm / structure-check), 150 queries per seed.
END-TO-END QUALITY MODEL (assumption): q = clip(base + G*hit@5 - H*offdomain@5 + noise), base ~N(.45,.10), G=.30, H=.10, k=5; hit@5 = gold paragraph in the 5 contexts, offdomain@5 = share of contexts from another domain than the task's (common random numbers across arms).
Arms: none | dense raw | dense+spell | hybrid z(.7)+BM25 raw | hybrid+spell (BEST FAIR POOLED, best on tune) | domain arms: router (cent / knn = domain vote of the pooled top-10 / fuse / lr / lrk) -> `H` hard in-domain index (z within the domain index), `P` pooled hybrid + lam*P(domain) prior, `M` pooled hybrid masked to the top-m domains; optional margin gate tau; ALL domain arms are disabled by a PRE-DECLARED label-structure self-check (dense-kNN label purity excess over base rate >= .15 on a held-aside doc bucket; not tuned). `oracle` = true-domain index/mask.
Tuned on seeds 1-8 (grid 5 routers x {H tau 0,.2,.4; P lam .5..16; M m 1-3 x tau 0,.2}; objective = mean e2e gain over the 3 non-control worlds): frozen = `P|knn|l16.0` (lambda grid extended 4 -> 16 before any held run; the curve is flat from 8 to 16).

(`*` = CI excludes 0). none -> pooled hybrid+spell: +.10..+.16 e2e (hit@5 .35-.65); spell alone on this 50%-typo mix: hybrid raw -> +spell hit@5 +.007..+.023 (q +.003..+.008; syn10 -.001 held / +.003 confirm). Oracle domain (true labels) headroom over pooled: dq +.039..+.084 on the real worlds, hit@5 +.04..+.14; the router realises ~25-40% of the dq and none of the hit@5.
Findings:
1. The e2e gain of the domain-prioritised arm (+.010..+.021 on both REAL worlds, Holm-significant, replicated on confirm) comes ENTIRELY from the off-domain-context harm term I put into the quality model: retrieval recall is flat (hit@5 -.011..+.007) and MRR ~0 (-.007..+.003) while off-domain context drops 27%->13% (pydoc9) and 41%->21% (crates8). Sensitivity (held, frozen - pooled dq): H=0 -> +.002 / -.003 / .000 (nothing); H=.10 -> +.017/+.016; H=.20 -> +.032/+.035; G=.15/.45 -> +.016/+.018 and +.016/+.013; k=3 -> +.008/+.015, k=8 -> +.020/+.018 (`results/h20_retrieval_sens_held.json`). So: domain-prioritised retrieval improves PURITY of the context, not recall; whether purity matters downstream is the unverified assumption.
2. On the confusable (lowest domain-specificity tertile of the held pool) queries the prior costs recall: hit@5 +.011 / -.039 (held), -.016 / -.046 (confirm) on pydoc9 / crates8 for q +.025/+.010 / +.016/+.010 -- the quality gain survives only through the harm term. Typo and clean queries behave alike.
3. Hard domain-index arms (`H`) and top-1 masks (`M`) give the same e2e gain (+.018..+.020 crates8, +.012 pydoc9 confirm) and a small MRR gain from in-index z-normalisation, but also no recall gain; kNN-vote routing (router accuracy .78-.99) was the best router on tune: it is a function of the pooled top-10 itself, so it adds no information, only a diversity-reducing prior. A trained logistic-regression router and the dense-centroid router were not better on tune (post-held addition, see below).
4. syn10 (SYNTHETIC; purity .99, queries carry unique entities, pooled already off-domain 1%): ties (-.0009, TOST-equivalent); no headroom for domain routing (oracle also +.002). This is the g1-style templated-corpus failure mode: where domain information is already in the words, partitioning buys nothing.
5. No-domain-structure control: label purity excess .001/-.011/.001 -> the self-check turns domain mode off and every domain arm is IDENTICAL to pooled (0.000 diff; this is a guard working, i.e. a tie by construction of the guard, not evidence the router is harmless). WITHOUT the check (`#nocheck` arm) the same arm loses recall: q -.033/-.042/-.022, hit@5 -.096/-.111/-.068 (confirm, results/h20_retrieval_confirm.json).
6. Hybrid z+BM25 over dense+spell: replicated again (confirm hit@5 .63/.64/.37 vs .54/.59/.26; q +.02..+.035).
Pooled hybrid + spell remains the primary retrieval; the domain prior is an optional purity filter.

## NEGATIVES / LIMITS (read first)
1. Both headlines are conditional on assumed outcome models I wrote (persona bonus b; off-domain harm H). They show how much of an ASSUMED effect routing captures and where it hurts, not that personas or domain partitions help a real LLM. Real validation requires graded real traffic (A/B of role prompts; off-domain-context ablation).
2. Persona: the only robust results are the arithmetic one (gain ~ acc*b - (1-acc)*p) and the safety result for the online A/B gate; learned role routing and per-agent gating are negative/neutral. Agent routing headroom dwarfs the persona effect in these worlds.
3. Retrieval: real text is python docstrings and crate READMEs (technical English); finance / economics / psychology / linguistics / history / business roles have NO real text on disk -> only the synthetic syn10 world covers them (and it has no headroom). 7-domain real worlds with provenance labels; paragraphs, not research tasks; queries are held-out sentences (domain tokens usually present).
4. DISCLOSED post-hoc changes: (a) retrieval: I looked at held-out results of the first pipeline (frozen `P|knn|l16.0`, saved as results/h20_retrieval_held_v1.*) and then (i) changed the harm model of the shuffled controls to use the TRUE domain (v1 charged arbitrary shuffled labels), (ii) added LR routers `lr`, `lrk` to the grid. Tune seeds again picked the same arm; confirm 61-90 was never seen before the freeze. (b) persona: I looked at held results of the first run (kept in results/h20_v1_logs/), then separated the role-exploration RNG stream from the agent-selection stream (zero-effect worlds now tie bit-identically; before, shared-stream noise gave spurious +.02 in G2) and widened the gate grid (tau 0..3, eps_g up to .3); re-tuned on seeds 1-8, held/confirm re-run once each.
5. Best fair baseline was selected per world on the evaluated seeds (conservative for treatments). Treatments reuse the kweps chooser, so a possibly better agent router would not change the role contrasts but would shrink the relative size of any persona gain.
6. Tuned hyper-parameters at grid edges: retrieval lambda (flat 8-16), persona gate z 1.28 (grid max), tau 1; gate_static tuned to never fire.
7. kNN purity self-check threshold (.15 excess) is pre-declared, not tuned; real corpora with weak but real partition structure could fall below it and lose the (small) gain.
8. Latencies/cost not measured; domain prior = one extra vote over the already computed top-10 (no extra embedding, no extra LLM call). Role prompt cost +60 tokens per role call (gate uses the role on 4-23% of calls).
