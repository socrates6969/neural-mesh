## 1. The world (fixed before policies, except the disclosed post-hoc items in section 6)
* Session = 3-8 dependent steps (mean 5.5), step types `search`, `db`, `read`, `compute`, `synth`; values are REAL integers, so a wrong upstream value propagates by arithmetic. Truth is computed at build time.
  `search` returns a document id (a miss is VISIBLE/empty with prob `p_vis`=.5, else a silent wrong document); `read` extracts a number from the document it was given (imperfect extractor: distractor number or digit slip; a wrong doc gives a faithful reading of the wrong doc); `db` = keyed lookup (wrong query -> a plausible wrong row; transcription slip unless the exact lookup tool is used; keys can come from earlier steps = joins that can be poisoned); `compute` = mental arithmetic (error prob grows with operands) or the REAL exact calculator (tool formulation errors are real operator mutations evaluated by `Calc`); `synth` combines facts (omits/mis-sums on error).
* Hidden per-agent per-step-type competence (8 agents; price per agent as h11 `Cap`); agent noise per (task, step, agent) fixed across arms (common random numbers). Generator A (6 worlds): template sessions (facts -> compute -> synth), specialist pool (2 generalists .66, 5 type specialists .90/.48, 1 weak). Generator B (5 worlds): random interleaved DAGs (fact blocks, keyed joins, computes), latent-factor agents, noisier extraction/arithmetic. 17 worlds = 6 A + 5 B + 6 controls (single-step, independent steps, no-info corpus, rare-errors+expensive-verifier, equal agents, one dominant agent).
* Verification (per step, imperfect, priced, sees LOCAL errors only: it can flag a wrong extraction/query/arithmetic slip but NOT a wrong input): search title check (recall .85 / false-flag .06), db independent re-query (.70/.08), read source-span check (.75/.06; no-source .95), compute tool re-computation (.97/.01), synth consistency (.85/.04), READ cross-source agreement (global: sees a wrong document; second source exists w.p. .6; conflicts .12; recall .90). `vq` blends recall toward the false-flag rate (vq=0 uninformative).
* Cost (h11 TE model, 1 reference call S_REF = 1900 TE = 500 prompt + 350x4 completion): agent call = price x (500 + 60/dep + 1400); retrieval .05 call + 300 TE injected chunk; tool step +20% + .1 call; verifier call = type price (.10-.55 call) x `vscale`. Session BUDGET = beta x steps x S_REF (beta 2.5; extras = verification/retries are blocked when the budget cannot cover them after reserving the remaining steps' base calls). Single-shot is charged step-units like g18.
* Grading: per-step exact-match; graded step quality = 1 exact, else max(.3 if the step was faithful on wrong inputs, .5 x near-miss credit); session graded quality = mean over steps; `ok` = ALL steps exact (headline), `fin` = final answer exact. Delayed (15 tasks, 60%, noise .05) graded feedback to every learner. 1000 sessions per run.

## 2. Arms
Fair single-shot (one router decision per task, whole task done by one agent, no retrieval/tools): ss-keyword, ss-eps, ss-pts, ss-hebr, ss-warm, ss-safe (best of 6 per world on the held seeds = conservative). STRONG fair controls: `ss-react` (single agent, retrieval + exact tools inside its loop, no decomposition/verification/replan) and `ss-bok3` (3 agents each do the session, plurality of finals; 3x cost).
Levels (cumulative): L1 decompose+route per step type; L2 + per-step retrieval; L2t + tools (exact calculator, exact lookup); L3x + per-step verification + retry on another agent (always verify); L4 = L3x with `verifygate::PosteriorGate` (verify iff (1-m)*rv >= cv, m = own delayed-graded mean quality of (agent, step type)); L4o = g18 online stopping (comparison); L5 = L4 + replan-on-failure (reformulate failed searches/db queries: each level halves the miss prob; visible empty results reformulate without a verifier call); BoK = L2t + per-step best-of-3 vote; `Stack` (pre-declared before any run) = L5 + cross-source READ verification (+ re-search of the document on a cross flag) + vote-instead-of-verify when the posterior is low (theta tuned); L4w / Stack-w = per-world gate scale tuned on seeds 1-8. Leave-one-out ablations of Stack: no retrieval / tools / verification / gate / replan / routing (random) / cross / vote. Reference rows (not policies): oracle-single, oracle-decomp, oracle-stack.
Tuning (seeds 1-8 only; objective over all 17 worlds): baselines (eps (1,.05), pts 1, warm k 3), step-router k (20, plateau), gate rv in {.25..32} (picks 32 = plateau .7461-.7468 over rv 8-32: the gate degenerates to "verify almost always" at mu=.03), online R (32, plateau), vote theta (.45). Held 31-60, confirm 61-90 with the SAME frozen tuning (tuning always reruns on seeds 1-8, deterministic), paired 95% t-CI, Holm per family (F1 level vs best plain baseline, F1s vs best strong, F2 vs previous level, F4 vs ss-react, F5 ablation vs Stack, F3 sample efficiency), >=2 independent generators (A, B; same-seed-protocol, NOT fresh worlds on confirm), controls with pre-declared TOST margins (+-.01 graded q, +-.02 all-correct).

## 4. Where the whole stack ties or LOSES (read these first)
1. The pre-declared whole stack (`Stack`) LOSES to its own sub-stack L5 in 5/6 (A), 4/5 (B) and 4/6 (controls) worlds (Holm, both seed sets): -.036 ok (A), -.064 (B), -.047 (controls) at +.4..+.9 calls, because of the cross-source READ verification; the vote adds nothing. The best arm everywhere is L5 = retrieval + exact tools + per-step verification + gate + replan. (Stack-w, the per-world gate-scale version, is within .01 ok of Stack in A/B and ~.3 calls cheaper in A.)
2. Decomposition+routing itself is a win only when specialists differ across step types (generator A: +.09 q / +.11 ok over a single agent with the same retrieval and tools, 6/6 Holm WIN) and a small LOSS or tie when one agent dominates (generator B +.001, ctl-dominant -.05, ctl-single-step -.018 for L1).
3. The learned/posterior gate and online stopping do not beat always-verify at mu .03 in the main worlds (tied in 15/17), and recover only about half of the waste in the rare-error/expensive-verifier extras.
4. Verification is bought, not free: +2.8..+3.4 calls per session; it is not cost-neutral in the controls (ok-per-cost -.019) and it is useless with an uninformative verifier or a budget that cannot pay for it.
5. A useless corpus (ctl-noinfo) turns every retrieval-based arm into a LOSS (-.04..-.09 q) at 1.1-2.7x cost: nothing here abstains.
6. Sample efficiency: no learning-speed advantage was observed for any level (0/0/17).

## 5. What I would claim (and not)
Supported in this simulation (both generators, both seed sets): retrieval + exact tools + per-step source verification + replan-on-failure take the all-steps-correct rate of a 5.5-step session from ~.01 (best fair single shot) / .14 (A), .20 (B), .40 (controls) (single agent with retrieval+tools) to .68 / .48 / .64 (L5) at ~1.4x the cost of ss-react; the sizes are set by my world (kmem, hq, p_vis, verifier recall) and the sensitivity table says where they vanish. NOT supported: that the pre-declared whole stack beats its simpler sub-stack (it does not), that a learned gate saves cost where verification pays, that decomposition helps when one agent dominates, that anything here is robust to a corpus without the answers, or that any number transfers to real LLM traffic.

## 7. Limits
Agents are probability models with hidden competence, not LLMs; retrieval/extraction/verifier error models and prices (h11 TE, verifier recall/false-flag table) are my assumptions; the verifier cannot see wrong inputs by construction (the reason verification must be per step), the corpus always contains the answers except ctl-noinfo, agents trust retrieved documents (no abstain/fallback), cross-source verification is modeled as one independent second read, retrieval is an auto-query with a fixed hit model (no real index), budget is a soft reserve rule, no latency/fan-out modelled, no real tokenizers or provider caching, memo/cache not tested. Costs are TE counts, not bills. Machine: shared 16 GB box, counts/ratios only.
