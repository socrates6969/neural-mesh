# lessons_h18 (R9-B domain math tools; all synthetic-until-validated)
- Exact domain tools are cheap to make correct, and an independent verifier (second algorithm / invariant) catches 100% of non-common-mode evaluator bugs (0% for a re-run "shared" verifier, 0 false rejects, 44 mutants x 3 sets); it also found a real tool bug (sig-fig "50") that unit tests missed. Common-mode constants/tables are invisible to it (0%).
- Word-problem -> spec extraction is the bottleneck, not the tools: seen-phrasing 94-97% right, unseen-phrasing 34-41% (conf>=.9 is 99.7% right, so confidence is the usable signal); "always call the tool on the extracted spec" is +0.00 / -0.05 vs the best plain baseline because extraction errors (-0.13 / -0.21) cancel the offload gain (+0.13 / +0.16 with a clean spec).
- What pays: confidence-gated tool use (rule conf>=0.7: +0.076..+0.081 at 1.2x cost) and verifying/retrying the model's own answer against the extracted spec (+0.06 at 1.45x), tiered together +0.085..+0.090 at 1.3x; a 3-vote majority needs 30 cost for the same gain. A learned selector loses to the one-parameter rule by -0.035 (second time after g21).
- Verifying correct-evaluator tool output is worth ~0 (+0.0003); verification pays against evaluator bugs (+0.1..+2.3 pp end to end, independent vs shared) and as a check on the model's direct answer.
- The lift lives in many-step problems (>=7 steps: +0.13..+0.15), none for <=3 steps / easy business ratios, and vanishes when text is mostly unseen phrasing or the plain model is near-perfect (error x0.25); never judge a tool arm without the unseen-share and error-scale sweeps.
- Controls: an ungated extractor fires on 12-15% of prose (-0.11..-0.13 correctness); gated arms are TOST-equivalent at +-0.01 (rule: exactly 0, cost +0.3 for the extractor call).
- Trap seen: rewarding "verifier accepted" in the selector rewards wrong-but-accepted specs; weight graded correctness (fit_w 0.25 beat 0.5).
