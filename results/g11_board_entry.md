## W12 (G11) - learned TEAM model + greedy search: real opt-in capability or by-construction artifact?

Files (all mine): `src/bin/g11_team.rs`, `src/bin/g11_common/{mod,world,base,learn}.rs`, `results/g11_team_*.{json,log}`, `results/g11_run_all.sh`,
`results/g11_proposed_patch.md`, this file. No `src/*.rs` touched, no crates, no commits. Everything is simulation; nothing here is evidence about real agents or any
claim of intelligence - it is a measurement of an online regression + greedy search against the repo's routers.

### What was built
* **New worlds** (independent of W7: variable SET of requirement tags + irrelevant `dom:` tag + 30% random `ctx:` tag; NOISY GRADED reward `clamp(v + 0.2 z, 0, 1)`, z pre-drawn per task = common random numbers;
  primary metric = noise-free expected team value `v` of the chosen teams, policies never see it; realized reward also logged). Value structures:
  RC = soft-OR coverage of weighted skill demands (submodular, redundancy diminishing; +RC-drift: a third of the agents' skills are redrawn at T/2; +RC-L: N=24,K=5);
  ROLE = 3 of 5 roles needed, product (AND) of per-role best quality, duplicate-role penalty; THR = prod of sigmoid(sum of agent capabilities - theta) (additive INSIDE a steep monotone link, i.e. NEAR the additive class);
  LAT = additive + pairwise latent-diversity = **own class BY CONSTRUCTION** (positive control, not independent evidence); C-SEP, C-SEPT = separable controls (C-SEPT has a trap keyword map on half of the types).
  **set 1** = these 8 worlds, frozen before any policy ran. **set 2** = `-K` variants (RC-K, RC-drift-K, RC-L-K, ROLE-K, THR-K, LAT-K) with half of the keyword "obvious leads" replaced by random agents - ADDED AFTER the first dev run showed
  `seq:keyword` (a perfect hand-written table) ~ oracle in RC/ROLE, i.e. nothing for a learner to add (post hoc, flagged). **set 3** = COMP (type-conditioned hidden complementary pair, distinct pairs) and COMP-X (3 hidden pairs, type t rewards pair t mod 3 and PENALISES the other two: a task-conditioned interaction a global pairwise term cannot represent) - added after set 2, before the final held/confirm runs.
* **Learned team model** (own implementation, `learn.rs`): `value = b0 + sum_{a in team}(g_a + mean_{f in task} H[f][a]) (+ sum_{a<b} J_ab)`, online NLMS on the team reward, keyword map only as prior mass `rho` on H[f][lead] (the same information keyword/warm/guarded baselines get), interned string features (world-agnostic), plain greedy (exact for the additive model) + eps swap.
  Arms: **L-add** (additive), **L-pair** (+pairwise J), **L-gate** (both trained; pair model USED only when a prequential z-test says it predicts the next reward better), **L-full** (L-gate + causal controller gate: randomized choice between the learner and `seq:guarded-safe` with prob q, only randomized decisions feed the per-controller means, both learn from every played team).
  Dev-time addition: a count-based step boost `step *= 1 + boost/(1 + n_cell/30)` (found on dev seeds 101-130 / tune seeds while fixing the separable-control regression; the gates did NOT fix it, the boost did).
* **Baselines** (repo routers unchanged): seq-with-team-credit {keyword, eps-greedy, pooled-thompson, hebbian-robust, warm(hebR), guarded-safe} each tuned PER WORLD on seeds 1-8 over the repo grid (12 eps, 4 pts, 12 warm), plus `NeuralMesh(team_size=K)` with guarded-safe and hebbian-robust leaders. The "best fair baseline" per world is picked on the EVALUATION seeds (conservative; it is a max over ~8 candidates).
* **Protocol**: all tuning on seeds 1-8 (learned configs: ONE pooled config over all 16 worlds incl. controls = conservative; `--tune perworld` = generous); held 31-60, fresh confirm 61-90; paired 95% t-CI on v vs best fair; Holm within each world set (set 1: 32 cells, set 2: 24, set 3: 8); controls: TOST +-0.01 and a one-sided non-inferiority test (margin -0.01), Holm; `--noise 0.1|0.4` sensitivity.
  Pooled-tuned config (seeds 1-8): `lr 0.1, l2 5e-4, eps 0.02, c1 0.1, rho 0.3, boost 4` (L-add); L-pair c1 0, c2 0.05; gate zthr 2.5; controller q 0.2, margin 0.

### Overall answer to the brief
* **Real or artifact?** Real for the additive part, within simulation: wins vs per-world-tuned baselines and vs the mesh in 2-3 independent generators that are outside (RC, ROLE) or only near (THR) its model class, replicated on held / fresh confirm / per-world tuning, cheap (~1 us, 6-16 KB). Not a by-construction artifact of one generator. But it is NOT "learned team model beats the repo" unconditionally: against a perfect hand-written keyword table it is 0.4-1.5 points worse (set 1), and against a half-wrong table it is 5-13 points better (set 2).
* **Pairwise synergy term**: artifact of worlds that are pairwise by construction (W7's planted QUBO, LAT, distinct-pair COMP); no robust gain, hurts coverage worlds. Do not merge.
* **Gates**: pair gate inert; causal controller gate cannot resolve the relevant gaps in ~2500 decisions and costs 1-3 points where the learner helps. Do not merge.
* **Harmless?** At noise 0.2 yes (non-inferior in both controls, wins C-SEP), but not noise-robust (C-SEPT regresses at 0.1 and 0.4) and TOST +-0.01 is unattainable. Needs real traces before anything is defaulted; opt-in only.

### Process / contamination notes (read before trusting)
* Order: set-1 worlds + learner written and frozen; first dev run (seeds 101-130) showed keyword ~ oracle in RC/ROLE and a control loss; then (a) set-2 worlds, (b) count-based boost + rho 0.3 in the grid + a gate-specific learner config, (c) `--tune perworld`, (d) set 3 (COMP, COMP-X), (e) non-inferiority test, ablation vs L-add, `--noise`. I looked at the held/confirm/perworld numbers of the 14-world version once (before COMP/COMP-X/NI/ablation were added); the learner and worlds 1-14 were not changed after that and the pooled tuning picked the same configs when re-run with 16 worlds. All reported numbers are from the final binary (`g11_run_all.sh`). `results/g11_team_dev.*` is from the mid-development (pre-boost, 14-world) binary and is kept only as a record; do not cite it.
* Tuning: seeds 1-8 only (baselines per world and per family; learned configs pooled over all 16 worlds incl. controls, or per world with `--tune perworld`). Seeds: world seed = eval seed, policy rng = seed*1000003+17. The best fair baseline is chosen on the evaluation seeds (conservative, winner's-curse against the learner).
* Holm is applied within each world set separately (sets are different families and were added at different times); the TOST/NI Holm families are the 8 control cells.
* Unit tests (4, pass): world determinism and oracle > random for every world, default noise 0.2, NLMS fits a repeated sample, greedy+swap polish optimal on >= 45/60 random pairwise instances and exact on additive ones.
* Timing/bytes are single-run wall clock on a shared 16 GB box (min of 3 repeats); the allocation counter measures live heap, not RSS.
