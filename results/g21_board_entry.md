### VERIFY REQUEST — W22 — G21-A SPEC EXTRACTOR (`g21_extract`, `g21_common/{nlgen,extract}.rs`)
What it is: deterministic, std-only, rule-based: tokenizer (dates/#ids/thousands separators/hyphen joiners), number-word folding (incl. decimals, typo-tolerant in math context), fuzzy lexicon (Damerau<=1, stoplist-guarded), one candidate extractor per kind (arith: infix / nested "the sum of .. and .." / procedural "start with .. add .." ; units: unit lexicon incl. compounds, attached vs target role, dimension-group filter; csp: relation scanning + domain clause; sym: two-sided relation; prog: six program templates; lookup), multiplicative-penalty CONFIDENCE (unused numbers, fuzzy fixes, ambiguous segments, a typo-eaten operator "sandwich", discussion verbs "explain/discuss/summarise" x0.35, competing kinds) and ABSTENTION (spec = None). World side: `nlgen.rs` renders each g13 canonical spec as text with levels L0 near-canonical / L1 varied phrasing, tree and procedural multi-step sentences / L2 number words + thousands separators + distractor numbers (dates, tickets, "within 30 seconds") / L3 typos / L4 degraded (an operand deleted or a conflicting number inserted), prose tasks with arithmetic-looking fragments (hard negatives), and an UNSEEN bank of phrasings (other operator words, unit spellings, sentence frames) the extractor was not developed against. Accuracy is SEMANTIC: the extracted spec is run through the REAL tool and compared with ground truth (exact-string match is also reported; it is ~50% only because the extractor parenthesises fully).
